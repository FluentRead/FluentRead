# FluentRead 浏览器测试共同契约

两个测试 skill 共用此文件。选择构建产物、首次启动、修改采集或排查启动/焦点问题时读取，同一会话无需重复加载。

## 构建产物复用

- 两套验证使用同一工作树，且源码状态、依赖与工具链、构建配置、开发或生产模式和浏览器目标一致时，共用一次构建。已有产物满足条件且来源可核对时，直接复用。各自通过 `--extension-dir` 传同一个绝对路径，在证据中记录对应的产物路径和构建日志。
- 核对实际构建输入，包括未提交和未跟踪的相关文件。输入或目标变化、来源无法核对时，重新构建所需目标。两套测试运行期间，产物目录保持稳定。
- 每套测试使用独立临时 profile 和独立证据目录，保留完整诊断及截图。交付验证使用生产产物运行本次相关专项。

## 回归测试范围

- 日常开发、修复、PR 提交、合并和普通交付只运行与本次改动及其直接影响范围相关的针对性回归测试，不默认运行全量回归。
- 只有用户明确要求全量回归，或进入用户要求的正式发版流程、在最终发布前的发版时刻，才运行全量测试。普通交付、PR 合并和生产构建验证不等同于正式发版。
- 根据改动选择相关测试文件、用例、UI 专项和站点子集；共享核心改动覆盖受影响的关键链路，但不得据此自动扩大为全量套件或完整站点矩阵。失败后先定位并重跑相关范围。
- 执行前检查命令默认范围，显式指定筛选条件；脚本默认全量时不得直接无筛选运行。不支持筛选时使用可限定范围的测试入口，不得静默退回全量。
- 报告实际测试范围、结果和未覆盖项，不能将针对性回归通过描述为全量通过。下文的断言与覆盖清单按所选范围适用，不要求每次全部执行。


## 运行时错误与告警门禁

测试和回归必须同时检查功能与运行时诊断。选定范围内出现 FluentRead 自身的错误或告警，必须定位根因、修复并重跑相关用例；不能因译文已出现或构建成功而判为通过。

- 在页面导航、扩展 UI 加载和测试动作前注册采集，覆盖网页内容脚本的隔离世界、popup/options、扩展后台及本轮新启动/重启的 Service Worker。收集 `console.warn/error`、未捕获异常、未处理 Promise rejection，以及扩展 API 失败；仅监听网页 `pageerror` 不足以覆盖内容脚本。优先使用 CDP `Runtime.exceptionThrown` / `Runtime.consoleAPICalled` 与执行上下文归属；必要时检查本轮隔离 profile 的扩展管理页错误记录，禁止连接日常 profile。
- 对本次相关流程检查首次加载、操作、恢复/重试与卸载，涉及重载时检查重载后的新后台；不因此扩大为无关功能的全量回归。任何采集空窗、不可观测 surface 或 CDP 附着失败都要记录，不能将“没有采集到”写成“没有错误”。
- 报告保留级别、surface/执行上下文、页面 URL、来源脚本位置、堆栈、动作/阶段、时间与次数。失败或中断时也先保存诊断再清理浏览器；日志不得包含密钥、令牌或完整用户配置。
- 对宿主网页/第三方脚本噪声，凭脚本 URL、堆栈或执行上下文证明归属后单独列出。不能按整站、全部网络错误、`TypeError`、`toLowerCase` 或整段消息前缀忽略；归属不明须保留并调查。
- 故意注入失败的负向测试，须限定用例、阶段、来源、精确错误和次数，并验证恢复；将命中的预期诊断留在报告，不能删除原始证据或抑制产品日志。已有问题也不能自动加入白名单。
- 交付报告列出错误/告警计数、已修复项、复测结果、排除项依据与采集缺口。自身问题尚未修复或证据不足时标为未通过/未验证，不能宣称运行时干净；外部服务/站点限制单独说明，不通过吞异常或关闭功能掩盖。

随附 `scripts/run-toggle-test.cjs` 的诊断摘要必须与 DOM 断言一起审查；项目自带站点脚本若缺少上述采集，先补充或用本轮诊断包装器，不能沿用仅检查译文的通过结论。

修改随附诊断采集器时运行 `node --test <this-skill>/scripts/runtime-diagnostics.test.cjs`，并用隔离真实浏览器复验 CDP 采集；事件夹具通过不能替代真实浏览器证据。


## 窗口定位

本机 `--background` 按 `DeskPad Display` → 副屏 → 主屏的顺序选屏。共用 helper 在启动前读取 macOS 显示器布局，给隔离 Edge 传入选中屏幕的坐标。每次创建测试页签时重新读取布局并校验窗口边界。显示器断开、不可唯一识别或无法容纳窗口时，尝试顺序中的下一块屏。每次尝试都维持后台校验。普通页面手势使用 CDP。

使用独立临时 profile 和 `newPageWithoutForeground()` 创建测试页。测试浏览器的窗口保持正常尺寸和可见状态，切换标签页使用 `activateExtensionTabWithoutForeground()`。

默认命令沿用自动顺序。用户明确传入 `--display name:<显示器名称>` 或 `FLUENTREAD_TEST_DISPLAY` 时，锁定该目标。真实系统级输入按本轮授权使用 `--headed`。

运行仓库自带的后台脚本时，将 `--focus-safe-helper` 指向本技能的 `scripts/focus-safe-browser.cjs`。支持 `FLUENTREAD_FOCUS_SAFE_HELPER` 的入口也可以使用该变量。DeskPad 上的整屏证据用 `captureBackgroundDisplay(context, page, outputPath)`，以显示器 ID 保存 PNG。回退到实体屏时用 `page.screenshot()` 截取测试页面。报告记录实际显示器名称和 `displayRole`。

扩展工具栏、系统菜单或 DeskPad 设置等原生界面可用 Computer Use。核对具体应用和窗口，保留本轮的焦点授权边界。

运行 FluentRead 仓库自带的浏览器脚本前，先搜索 `bringToFront` 和直接的 `launchPersistentContext`。若脚本尚未采用等价的无前台启动机制，不要在用户工作期间直接运行；应使用 Skill 脚本、在 `/private/tmp` 中制作焦点安全的临时副本，或先取得用户允许前台测试。
