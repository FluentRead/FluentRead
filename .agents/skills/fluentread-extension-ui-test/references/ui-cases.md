# Popup 与 Options 专项断言

按所选套件适用，页面级翻译验证无需加载此文件。

## 准备

1. 将当前 FluentRead checkout 或 worktree 作为待测项目。
2. 运行 `git status --short`，保留用户已有改动。
3. 在该目录持续运行 `FLUENTREAD_DISABLE_BROWSER_RUNNER=1 pnpm dev`，等待 `.output/chrome-mv3-dev/manifest.json` 出现。
4. 调用 Codex 工作区依赖工具，获取捆绑 Node.js 与 Node 包目录。

专项开发循环使用 `.output/chrome-mv3-dev`；准备交付时先运行 `pnpm build`，并用 `.output/chrome-mv3` 重跑本次改动相关的专项套件。报告必须明确本轮使用的是 dev 还是 production 产物。


## 运行自动验证

使用绝对路径调用脚本：

```bash
<bundled-node> \
  <this-skill>/scripts/run-ui-test.cjs \
  --extension-dir <fluentread-checkout>/.output/chrome-mv3-dev \
  --playwright-root <bundled-node-packages> \
  --artifacts-dir /private/tmp/fluentread-ui-evidence \
  --suite popup
```

开发过程中按改动范围运行专项套件，避免每次都重复完整回归：

```bash
# popup、抽屉、服务选择器
.../run-ui-test.cjs --suite popup ...

# options 导航、通用设置、搜索与可访问性
.../run-ui-test.cjs --suite options ...

# 翻译服务目录、模型折叠、服务/模型内部滚动
.../run-ui-test.cjs --suite services ...

# 1024、820、390 像素布局
.../run-ui-test.cjs --suite responsive ...

# Shadow DOM 与宿主页面恶意 CSS 隔离
.../run-ui-test.cjs --suite isolation ...
```

`--suite` 默认为 `full`，也支持逗号组合，例如 `--suite options,services`。每次调用必须显式指定本次相关的专项，避免省略参数触发全量；上例的 `popup` 应按改动替换。专项套件仍会加载真实的 MV3 扩展和隔离 Edge profile，但只执行对应范围。`--suite full` 仅在正式发版时或用户明确要求全量回归时运行。

`--extension-dir` 可以指向 `.output/chrome-mv3-dev` 或 `.output/chrome-mv3`。不得在同一证据目录混用两种产物；开发专项与生产交付结果分别保存，避免把热更新状态误当成最终包结果。

脚本使用独立临时 profile，按 DeskPad、副屏、主屏的顺序为 Edge 选择正常显示窗口，并记录前台校验结果。需要整屏截图时使用[共同契约](../../fluentread-browser-translation-test/references/browser-contract.md#窗口定位)中的截图接口。

脚本必须使用临时 Edge 配置并真实加载扩展，直接访问清单声明的 popup 和 options 页面。不得把普通 Chrome 或 Edge 用户配置传给 `--profile-dir`。


## 必须通过的断言

1. 清单包含有效的 `action.default_popup` 和 `options_page` 或 `options_ui.page`。
2. popup 能完成 Vue 挂载，核心标题、主开关、语言选择、翻译按钮与六张快捷功能卡均可见。
3. popup 宽度不超过 400 CSS 像素、没有横向滚动，内容高度不超过 Chrome 常见的 600 CSS 像素上限。
4. popup 底部同一行显示左侧统计、中间带本地图标的“开源项目”入口和右侧“清除缓存”操作；入口必须指向 `https://github.com/Bistutu/FluentRead`，并使用新标签页打开；不要只验证静态文字。
5. 主开关的暂停和恢复状态正确联动翻译按钮及四张功能卡；状态卡、品牌色开关和键盘 Tab 均可用。
6. popup 逐 case 覆盖源语言自动检测、全部目标语言、全部可用翻译服务，以及翻译加载、成功、恢复、禁用响应、无内容脚本错误；成功翻译后按钮必须进入明确的已翻译视觉状态，恢复原文后必须清除该状态，失败时不得误显示已翻译状态；缓存加载、成功和错误分支也必须覆盖。翻译服务选择器必须验证统一风格的“常用服务”列表、默认收起的“更多服务”、展开/收起、常用与更多服务逐项选择、Escape 和点击外部关闭，并确认当前服务在更多列表中时会自动保持可见；常用服务和更多服务的每个选项都必须渲染本地 SVG 服务图标。
7. 悬停、划词/圈选、悬浮球、译文显示、图片翻译和视频字幕六个抽屉都能打开、操作和关闭：包括每个枚举值、自定义快捷键确认/取消、主题、样式、开关和位置状态，且设置在 popup 重载后仍然存在。
8. 配置持久化回归必须覆盖短生命周期页面：在 popup 和 options 中分别修改至少一个布尔开关、语言、翻译服务和抽屉设置；等待界面反馈后关闭 popup 或设置页，再重新打开并断言所有修改仍保持。Firefox 还必须执行“options 修改 → 关闭设置页 → 打开 popup → 断言相同值”的跨页面验证，不能只检查当前 DOM。若测试通过运行时消息或 storage watcher 触发保存，需记录保存请求已发出、后台响应成功及重开后的最终值。
   - 对每个失败 case 保存修改前值、修改后值、关闭动作、重开后的值和截图/日志证据；发现值恢复默认时必须保留浏览器控制台错误、扩展 storage 读写日志和复现步骤。
   - 测试必须包含快速关闭场景：修改 select/toggle 后立即关闭页面，验证后台持久化仍完成；同时包含连续两次修改，最终值必须胜出，不能被旧快照回写覆盖。
   - Chrome、Edge 和 Firefox 分别使用独立临时 profile。受控 Firefox 实例优先放到 DeskPad，前台交互按本轮授权执行。
   - 任何新增的持久化测试都应在单元测试中覆盖：消息发送成功、后台不可用时的安全降级、对象快照规范化、连续保存去重/最新值胜出和外部 storage 更新通知。
   - 如果现有脚本不能控制 Firefox，必须在交付报告中明确说明 Firefox 的手工/Computer Use 验证范围与证据，不得把 Edge 的通过结果推断为 Firefox 通过。
   - 持久化改动优先运行相关持久化用例；使用 `--suite persistence` 前先确认当前脚本支持该专项。普通交付不要求 `--suite full`。
   - 对 popup、options、持久化流程与配置历史至少各生成一张重开后的证据截图，截图中必须能看出修改后的配置值、版本号和时间，而不是只有空白页面或静态品牌区域。
   - 在清理浏览器前先导出测试摘要，至少包含 `persistenceCases`、`quickClose`、`crossPageSync`、`latestWriteWins` 和 `consoleErrors` 字段；清理后仍应能从报告定位证据文件。
   - 若浏览器重载或关闭导致保存请求未完成，测试应失败并报告最后一次配置快照，而不是静默跳过。
   - 扩展后台保存接口的消息名、响应状态和异常降级路径应从真实构建产物中验证，不能只在 mock 中断言。
9. popup 齿轮、四个抽屉内的“完整设置”链接都必须真实调用扩展 API 打开 options 页面，而不是只验证硬编码 URL。
10. options 页面能完成 Vue 挂载，八个导航分类及对应页面都唯一存在；每个导航按钮均能激活正确标题，并保证其他分类内容不可见；“关于流畅阅读”页面应显示版本、核心体验和项目入口。
11. 通用设置覆盖插件启停状态卡、翻译模式、默认目标语言、文本与视频翻译服务、24 种译文样式选择和选择后的实时预览；选择结果必须立即反映在预览并持久化。
12. 翻译服务页必须显示“机器翻译”和“AI翻译”分组；这里是配置以后网页翻译默认使用谁，不是点击某个服务后立即执行翻译，因此应明确表达“默认服务/默认模型”的语义：上方选择服务与模型，下方显示当前服务或模型对应的连接配置；服务目录主工作区应铺满右侧可用区域，不被过窄的外层卡片留白限制；服务栏、详情头部和模型卡片必须使用本地图标，不能回退成字母占位；所有需要模型的 AI 翻译服务都必须提供“自定义模型”入口（Coze/扣子机器人模式除外），并验证逐项显示；OpenAI 默认最多展示 4 个常用模型，其余模型收进“更多模型”，并验证展开、收起、选择、搜索折叠模型和当前服务状态；连接参数旁的提示图标必须实际悬停显示对应说明，尤其是自定义模型和自定义请求体，不能只有图标没有提示。
    进入 options 服务页时必须记录 `[data-default-service]` 与 `[data-editing-service]`：点击另一项后只允许编辑状态和右侧配置内容变化；`data-default-service`、默认服务圆点和“当前默认”标记必须保持原值，编辑目标显示“正在配置”，点击原默认服务后恢复“当前默认”。左侧点击不得写入 `config.service`。
13. 设置页外层视口不得产生页面滚动；服务栏和展开后的模型网格必须各自拥有独立滚动区域。设置搜索同时通过快捷键与 OpenAI 跨分类跳转、跳转清空和无结果状态测试。
14. popup 和 options 不得出现重复 ID；popup 的可见交互控件必须拥有可访问名称，旧设置控件的缺失项必须记录为警告。
15. 在本地 HTTP 页面施加强制 `!important` 全局 CSS，悬浮球与划词翻译必须分别存在开放 Shadow Root，关键 position、尺寸和圆角的计算样式不得被宿主页面污染。
16. 深色 popup 以及 1440、1024、820、390 像素宽度的设置页都能正确渲染且没有横向滚动。
17. 扩展初次加载和 `chrome.runtime.reload()` 后都没有未处理的页面或 Service Worker 控制台错误，防止开发热重载再次创建重复菜单。
18. popup、四个抽屉、五个设置分类、服务模型目录、恶意 CSS 页面、深色 popup 与各窄屏设置页截图均成功生成。


## 人工复核

检查脚本输出的全部 PNG，重点确认：

- 信息层级、对齐、字体与色彩是否协调；
- popup 底部没有裁切；
- 抽屉从底部出现且遮罩合理；
- 设置页在桌面和窄屏下没有重叠、溢出或不可读区域；
- 翻译服务页的服务目录主工作区横向铺满右侧设置区域，左右不保留不必要的大块留白；服务目录内部仍保持服务栏和模型区域独立滚动；
- 设置页外层保持固定视口，服务列表与模型列表内部滚动；通用设置的开关卡、样式选择器和实时预览使用同一套圆角、边框、品牌色焦点状态；
- 左侧菜单分组清楚，八个分类点击后标题与内容确实切换；“关于流畅阅读”页面的品牌、版本与链接区域保持简洁统一；
- 服务列表分组、当前状态和模型卡片层级明确；“更多模型”收起时页面紧凑、展开后不拥挤，并且不出现伪造的“启用服务”状态；
- popup 翻译服务选择器使用站内统一的面板样式；常用服务一眼可见，其他服务默认收进“更多服务”，展开后列表可滚动且当前选择有明确勾选状态；
- popup 与设置页的服务项、详情头部和模型项使用同一套本地图标组件；常见服务有清晰的品牌化图形，未单独定制的服务也有统一几何图标，不出现裸字母占位或外部图片请求；
- `hostile-css-shadow-isolation.png` 中宿主页面保持故意破坏的样式，而悬浮球仍保持正常尺寸与圆形外观；
- 深色主题对比度足够。

如截图不符合预期，修改产品代码后保持开发服务运行并重复脚本。截图由自动选中的屏幕上的隔离后台窗口生成。只有必须使用前台或系统级交互时，才按本轮授权使用独立的 `--headed` 窗口。


## 交付

报告扩展目录、隔离浏览器、`launchMode`、`focusPolicy`、清单入口、实际运行的套件、布局指标、`caseCoverage` 逐 case 结果、交互断言、控制台错误计数及截图路径。最后运行 `git diff --check`，确认验证没有产生受版本控制的项目改动；最终报告基于本次实际运行的相关专项；仅正式发版或用户明确要求全量时提供完整 `--suite full` 结果。

清理时只关闭本次测试创建的 Edge 实例和临时 profile。报告中核对后台测试的 `windowPlacement.browserFrontmost=false`、`windowPlacement.displayName` 和窗口边界。使用 `--headed` 时记录居中后的 `windowPlacement`。
