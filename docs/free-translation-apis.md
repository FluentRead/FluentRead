# 免密钥翻译接口与自动降级

核对日期：2026-10-06。下列候选均不要求用户填写 API Key 或 Token，网页协议的临时签名由适配器处理。小额度可以作为后备；每家服务自己的额度、语言和请求大小限制仍然生效。

## 默认服务池

默认使用**智能加速**（兼容原 `balanced` 设置），按近期成功率、耗时与在途负载分配不同段落。新配置默认开启 16 个官方直连服务：微软、B站翻译、腾讯交互翻译、火山、谷歌、有道、金山词霸、Yandex、MyMemory、搜狗、Reverso、Apertium、阿里翻译、ModernMT、Lara、Lingvanex。

免费池只请求供应商自己运营的节点。DeepLX、Lingva 第三方代理已移出，旧顺序会剔除这两项，其余手动选择保留；不自动往已保存列表添加四个新服务。独立 DeepLX 服务的配置仍可单独使用。这里的“官方”表示节点归属，不意味着网页接口是有公开文档或 SLA 的云 API。

| 后备服务 | 接口性质 | 使用方式 |
| --- | --- | --- |
| 微软翻译 | Edge 网页内部接口，不是正式公开翻译 API | 保留已有免密钥调用方式 |
| 谷歌翻译 | Google 网页接口，不是 Google Cloud Translation 官方 API | 初始优先 `translateHtml` 原生批量，随后根据成功率、耗时与负载动态排序；保留 `translate_a/t` 与两个网页 RPC，移除零成功的 `translate_a/single`；无需用户密钥 |
| MyMemory | 官方公开查询 API | 无需注册、密钥或邮箱即可调用 |

网页端点的可调用性不等同于官方 API 额度或可用性承诺，可以在设置中停用。更多默认候选和可选候选见下文。

## B站 Index-Translate 免费文本 API

免费池新增「B站翻译」，固定调用 `https://index-translate.bilibili.com/v1/chat/completions`，模型为 `Index-Translate-35B-A3B`。无需 API Key、账号或本地模型；请求不携带 Cookie、用户凭据、自定义请求头或代理。只接入文本翻译，不调用语音识别或配音模型。

B站翻译同时提供「机器翻译 → B站翻译」独立入口和「免费翻译服务」中的节点，两者共用官方接口。独立入口无需任何配置，可设为默认服务，也可用于全文、划词、文档及字幕文本翻译；直接选择时只调用 B站。免费池中微软排第一，B站排第二并标注「推荐」，新配置默认开启。旧配置首次升级会开启 B站翻译，插入已启用的微软之后；没有启用微软时插在列表开头，保留其他节点的选择与相对顺序。迁移完成后，用户手动关闭会保持关闭，备份与恢复也保留该选择。节点复用启停、顺序、智能加速权重、连接检查、取消和失败换线；现有并发与超时预算保持不变。长文本按 2,000 Unicode 码点分块，保留换行、边缘空白和全文文本槽。思考模式固定关闭；截断或无效译文视为失败。

扩展后台自动移除本扩展发往 `index-translate.bilibili.com` 精确域名的 Origin 请求头，避免官方网关拒绝扩展来源；规则不影响宿主网页或其他域名。需要浏览器的 declarativeNetRequest 能力，其他运行环境取决于自身网络 transport；连接失败仍由免费池尝试其他已启用节点。无需手动配置该请求头规则。

官方公开免费接口并不意味着无限额度或长期可用保证；实际限流按照 HTTP 状态与 Retry-After 进入已有冷却逻辑。接口来源：[官方项目说明](https://github.com/bilibili/Index-Translate)、[官方调用示例](https://github.com/bilibili/Index-Translate/blob/main/inference/llm/call_api.py)。

## MyMemory 官方匿名接口

匿名每天可查询 **5,000 字符**。联系邮箱是可选项，留空也能使用；自愿提供有效联系邮箱后，官方限额为每天 **50,000 字符**。[官方使用限制](https://mymemory.translated.net/doc/usagelimits.php)

公开查询使用 `GET https://api.mymemory.translated.net/get`。必填参数为 `q` 和 `langpair=源语言|目标语言`，公开查询不要求 `key`。单次 `q` 最多 **500 UTF-8 字节**，不是 500 个中文字符。[官方接口规范](https://mymemory.translated.net/doc/spec.php)

FluentRead 保留换行和分段边缘空白，优先在空白或标点处分割超长文本，并保护全文翻译的内部文本槽标记。自动源语言使用本地保守检测；短英文单词、无法区分的共享汉字等不确定输入会跳过 MyMemory，继续尝试后面的服务，也可以手动选择源语言。

如果填写邮箱，它会作为 `de` 参数随请求发送给 MyMemory。FluentRead 只调用 `get` 查询，不调用 `set` 或导入接口，不上传翻译贡献，也不会自动购买额度。邮箱输入是本地草稿，完成有效地址后才保存，逐字输入不会被配置校验清空。邮箱设置常驻在服务列表下方，避免嵌套折叠和把同一行其他卡片撑高。

2026-09-05 曾用通用示例 `Hello world.` 和 `en|zh-CN` 对官方端点进行一次真实匿名请求，收到 HTTP 200、`responseStatus: 200`、`quotaFinished: false` 与译文“你好世界”。这是一次可用性证据，不代表所有地区和以后时间都可用；未发送用户网页内容或真实凭据。

## 设置与降级行为

在“完整设置 → 翻译服务 → 免费翻译服务”中选择模式和启用状态，至少保留一路。智能加速的分配参数由后台根据成功率、响应耗时和近期错误自动调整，用户无需设置或维护权重。免费链没有 Key 输入项，MyMemory 邮箱可留空。已有其他独立服务的凭据设置保持原有用途，不会被免费链读取、修改或作为后备调用。

点击“检查连接”会逐一检查完整免费服务目录，包括未开启的官方候选。全部 15 家统一列在“参与翻译的服务”中，不再折叠“更多服务”；每家独立返回结果，不用自动换线的成功代替单家结果。检查最多同时请求三家，每家沿用设置中的等待上限；只发送固定英文测试句，不发送网页内容。常规服务使用英语→简体中文，Apertium 使用其支持的英语→西班牙语；连接通过不代表支持中文。标题栏显示检查进度和通过/失败数量，每家服务直接显示未检查、等待检查、检查中、连接正常或连接失败。成功和失败都会显示本次测试耗时（毫秒），不计检查前的排队时间；正常响应优先使用后台测得的翻译耗时，失败或缺少耗时字段时使用本次检查请求到结束的时间（含消息往返）。未开启服务也保留本轮结果，便于决定是否启用。所有服务卡片保持等宽等高，失败原因集中在列表下方直接完整展示，不再撑高单张卡片；服务名和状态的悬停提示提供说明与测试语言对。再次检查会更新结果，切换正在配置的服务或修改相关连接参数会清除旧结果；检查不会改变启用列表或智能分配权重。

- 智能加速允许连续选择快且可靠的服务。耗时变慢立即反映，变快平滑恢复；亚秒级服务也有速度差异，正忙的服务减少分配机会。优先顺序仍按用户列表依次尝试，不启动竞争请求。
- 主请求明显变慢时，可以启动一个不同服务的备用请求，取首个有效译文并取消另一条。冷启动等待 1.5 秒，随后按近期耗时调整到 0.8–2 秒。只有启用的、未尝试过且符合冷却/并发/间隔限制的服务才有资格。
- 备用竞争受全局预算约束：每个后台运行实例初始允许一次，之后每五次成功补充一次，最多积存一次；每个文本最多启动一次竞争。失败立即换线，不在同一服务连续重试。
- 同时最多执行六条免费翻译任务，整个调度器额外最多一条竞争请求；不同节点可并行处理不同段落，批量输出保持输入顺序。微软每家最多两条在途请求并间隔 100 ms，其他每家一条；MyMemory、Lara、Lingvanex 间隔 1 秒，其余节点间隔 300 ms。上层设置的总并发和请求速率仍然生效。
- 默认每路最多等待 5 秒，可调整为 1–15 秒。单次调用（含批量文本）总预算最多 20 秒；排队、备用和回退共用截止时间，上层只可缩短，不能延长。免费翻译的单条、批量和视频入口不再重复全局“失败后最多重试”流程，其他服务的重试设置不变。
- HTTP 429 默认从 5 分钟起退避；401/403 和消失的固定端点从 6 小时起退避；每日额度耗尽从 24 小时起退避。网络错误、超时及服务端故障默认从 1 分钟起退避。连续失败会延长暂停，并增加少量随机延迟。
- 服务端提供有效 `Retry-After` 时遵循该时间，最长保护窗口为 7 天。文本长度和语言方向等请求错误不暂停服务处理其他文本。
- 暂停期间跳过该服务，到期只放行一个恢复探测，成功后解除冷却并更新性能统计。身份摘要、错误类别、失败次数和恢复时间保存在本地，使后台重启后继续遵守暂停时间。记录异步串行写入，合并挂起期间的变化，不延迟译文返回或换线。存储失败不会阻断翻译，但可能无法跨重启保留状态。
- 智能加速使用的成功率、响应耗时等性能信号由后台自动维护，保存在本地，仅用于服务分配和冷却恢复；用户无需设置权重。未进行连接检查时，服务开关旁仍可显示暂不可用、恢复中等运行状态；手动检查后显示本轮连接结果。每张已启用服务卡直接显示分流参考比例，列表上方显示合计，每 5 分钟刷新；运行信息不再使用折叠面板。后台随请求实时调整，实际分配还受忙碌程度和当前文本影响。
- 用户取消会停止整条链。全部服务不可用时显示失败，不无限重试；语言等请求参数错误只影响当前请求。
- 请求保持同一份配置快照；修改顺序后，新请求与旧缓存分开识别。新的等待策略只影响后续请求，迟到响应不能覆盖已取消的结果。

双语和仅译文模式共用文本槽翻译，HTML 骨架保留在本地。协议测试使用合成响应验证语言、分块、错误与取消，不能替代真实网络验证。实现依据公开协议和 FluentRead 现有架构独立完成，没有复制非零碎代码或修改参考仓库。

浏览器验证使用生产构建与临时 Edge profile，区分真实匿名 API 实测和本地故障注入。旧版完整 UI 技能脚本依赖已变更的导航选择器，完整套件未计为通过；当前功能使用独立专项验证。Firefox 与 userscript 的构建校验不等同于运行时浏览器验证。

## 智能加速的设计依据

参考 [Linkerd 的延迟感知负载分配](https://linkerd.io/2-edge/features/load-balancing/) 与 [gRPC 的延迟备用请求和节流](https://grpc.io/docs/guides/request-hedging/) 思路，在 FluentRead 现有 Vue/WXT 调度边界内独立实现，没有引入代理框架或复制其代码。只读对比 read-frog 的请求队列与批量重试后，保留 FluentRead 的多免费服务换线模式，避免叠加多层重试。

这里只承诺调度边界：无效原文回显、明显错语种和空响应仍被拒绝，不会为了速度展示或缓存无效结果。服务端限流、额度与语言支持仍然有效；受控故障计时不能代表不同地区的真实网络速度。
