# 翻译统计

打开 **设置 → 翻译统计**，查看翻译请求的规模和耗时，比较各翻译服务的响应速度与稳定性。

## 概览

- **翻译请求**：请求次数与成功率。失败和超时分开计数；翻译途中离开页面等取消的请求不算失败。
- **翻译文本量**：发送翻译的原文字符数、段落数和数据大小。
- **平均耗时**：从发起翻译到拿到译文的时间，并给出 P95、最长耗时和其中等待服务响应的时间。
- **缓存复用率**：直接使用已有译文、无需再次请求服务的段落比例。

可以按服务、模型和时间范围（今日、7 天、30 天）筛选，趋势图可切换请求次数、平均耗时和文本量。

## 比较翻译服务

**服务表现** 按服务和模型列出请求数、成功率、平均耗时、P95、最长耗时和平均规模。点击表头排序，点击一行只看该服务。

耗时只统计成功且实际请求了服务的翻译。缓存直接返回的结果几乎不耗时，会拉低平均值，因此不计入。P95 表示约 95% 的请求不超过这个时间，由耗时分布估算。

批量翻译一次包含多个段落，耗时自然更长；比较服务时可以参考每行的“约 X 字符/秒”。

## 免费翻译的各条线路

使用免费翻译时，一次请求可能先后尝试多条线路（微软、谷歌、有道等），失败会自动换下一条。**免费翻译线路** 表按线路列出尝试次数、成功率、平均耗时、P95、最长耗时和平均规模，可以据此判断哪条线路更快、哪条经常失败，再到 **翻译服务 → 免费翻译** 里调整启用范围或顺序。

因为失败会重试其他线路，线路的尝试次数之和通常多于请求数；线路耗时只统计成功的尝试。请求记录里也会显示该次请求实际用到的线路。

## 分布与失败原因

耗时分布和请求规模分布帮助判断慢请求是偶发还是普遍。失败原因按密钥或权限、频率或额度、超时、网络等分类；频率受限较多时，可以在 **高级选项** 中降低并发或每秒请求数。

## 请求记录

请求记录列出最近每一次翻译请求的时间、服务与模型、规模、来源、状态和耗时，可按来源和状态筛选，也可以按“最慢”排序找出耗时最长的请求。

| 来源 | 含义 |
| --- | --- |
| 请求服务 | 原文发送给翻译服务 |
| 缓存命中 | 全部译文来自翻译缓存 |
| 部分缓存 | 批量翻译中部分段落来自缓存，其余请求服务 |
| 合并请求 | 与正在进行的相同请求共用结果，不重复发送 |

## 保存与清除

统计保存在当前浏览器。请求记录保留最近 5,000 条；按小时汇总的数据保留 90 天，较长时间范围的汇总不受记录条数影响。点击 **清除统计** 删除全部统计，不影响翻译缓存、模型用量和设置。

AI 服务的 Token 用量见[模型用量](/guide/model-usage)。
