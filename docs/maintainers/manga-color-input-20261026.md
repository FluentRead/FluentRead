# 彩色识别输入与八类新增回归场景

候选基于 `172c713d5aed4fd11e00d35a17eea2ed9e7f7a5c`。锁定的 `ppu-paddle-ocr@6.6.0` 浏览器识别预处理将红通道复制到三个输入平面；同红值、不同绿蓝值的文字和背景因此可能变成相同输入。适配器借用原裁切的一次像素读回，在原张量构造处完整验证原批次、稳定排序、尺寸与补齐，再写回三个颜色通道。原检测、裁切、批处理和解码保持原流程，未读取或修改期望文字。

默认候选使用 BGR，依据上游配置选择；诊断另外固定比较 RGB，未根据输出为单张图片挑选通道。导出模型的颜色语义仍缺少独立模型卡契约，不能仅以配置证明。适配只替换该识别实例所持 provider 的 Tensor facade，不修改全局 ONNX 模块。未知批次关联拒绝本页，保留原图与首个错误。

部分透明颜色在源图的 Canvas 解码阶段已有预乘往返差异：原生前后相等不能证明原始 PNG 四通道完全保留，原始门禁仍失败。Atlas 的 `(800,1010)` 从 `[60,56,50,255]` 变成 `[245,240,217,255]`，同时违反原始与原生保护，属于真实画面改写问题。此次颜色输入修改没有解决它。

四组均完成原图恢复、缓存重显、关闭自有浏览器和删除临时 profile，没有清理错误。各组仍观察到一个去重后的 ONNX 节点分配 warning（两份原始观测），保留为 blocker；没有以已知 warning 分类把失败的功能验收改绿。原报告 `runs=0` 只来自 Offscreen 观察器，实际推理在独立 Worker，不能当作零推理或推理次数性能证据。

资源轨迹旧文件名只含 round，同一轮后景会覆盖前景的 `manga-round-1.json`。逐景摘要仍在原报告；被覆盖的详细轨迹无法补回。现将新运行的文件名加上实际流水场景序号，并验证 32 景五轮不会重名。本次历史文件不重写，不据其最后一景轨迹推断其他场景性能。

## 资源与模型复用

颜色适配与旧增强共享每页 2,000,000 像素准入，单裁切 262,144 像素；借用 RGBA 上限为 8 MB，在每批原生推理 await 前释放引用。适配器没有新增 Canvas、读回、会话或模型调用，但新增张量验证和通道写入有 CPU 成本；混合补齐批次的验证工作不只由借用像素数量决定。

独立真实识别模型实验保留原批次上下文、82 个裁切、三种固定模式、78 次前向。81 个可评分裁切的精确通过数由增强 RRR 的 67 提高到 BGR/RGB 的 72，包含上述空格退步。各模式均为 26 次前向、7,121,088 个输入 float；单轮原生总耗时约 10.12 / 10.05 / 10.06 秒，差别不足以证明提速，更不能证明优于参考项目的整条流水线。

回归共用显式固定模型目录，按字节数与 SHA-256 核对原四个生产资源（检测、识别、字典、LaMa，合计 237,406,681 字节）。本轮冻结启动器拒绝缺文件后的下载回退，四次准备均为缓存命中；附着后的自有 Offscreen/Worker 没有远程 HTTP(S) 请求。附着前和浏览器内部传输仍有观测缺口，不能声称全局零网络。每个临时 profile 仍需从本地导入模型，这属于本地 I/O。

参考项目为 [manga-image-translator 的固定提交](https://github.com/zyddnys/manga-image-translator/tree/d6de6ab62a7be6afc0d07a3184149cdefbcd32f2)。本轮借鉴其按文字检测、识别、修补和排版分别评估的思路，并研究 CTD 分割的实际能力；颜色适配仍按 FluentRead 的 WXT、TypeScript 和既有 SDK 接口独立实现，没有跨仓库运行时依赖。

CTD 仅在固定缓存中进行参考研究，没有加入产品资源或发布包。其 14 页 × 两通道共 28 次实际前向均不满足直接擦除安全条件，包含无字画面误遮罩和 Atlas 真字笔画遗漏；未把模型原始分割结果直接用于修补。这次只测原始模型分割，没有运行参考项目的全部细化与修补流程，不能将结果当作双方完整产品的优劣对比。

后续验收仍包括精确空白、不同底色的段落归属、注音识别、Atlas 画面保护、透明原始像素、运行时 warning，以及真实服务、语言质量和可比较的性能。当前结果不能支持“整页全部通过”或“优于参考项目”的结论。
