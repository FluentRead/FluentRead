# 原生 PDF 未领取结果页超时退出

本补丁在 main 已有的双时钟后台票据过期和创建取消机制之上，增加独立结果页超时退出，避免 MV3 后台自然休眠或重建后，已启动的结果页一直等待丢失的内存票据。

- 后台票据仍仅在内存，以原有六十秒和十六条边界管理。领取和过期释放正文引用并取消定时器。保留上游不主动关闭已创建窗口的策略，避免误关已由用户导航的窗口；结果页只处理自身仍未领取的生命周期。
- 有效 token 的结果页在等待配置水合之前启动六十秒计时器；收到有效正文后取消。null、异常或一直等待不会取消计时器。
- 到期先 dispose 再关闭；迟到的配置/claim 响应不会挂载卡片。已排队的定时回调也不能关闭已收到有效正文的结果页。
- 无 token 和 too-long 提示页不安装该计时器。正文、来源及票据不新增磁盘存储或日志。

## 验证范围

`nativePdfSelection` 与 `nativePdfSelectionPage` 定向测试包括后台模块 A 打开窗口、只移除 A 的定时器、重建模块 B 后保留原结果页，B 不持有票据，结果页仍自行退出。其它用例覆盖配置水合等待、claim 等待/null/异常、禁用、迟到响应、手动销毁及已领取卡片。

这不是全面孤儿窗口回收：页面未加载、脚本启动失败时没有页面计时器；页面冻结、浏览器或设备休眠会延后回调；期限从页面安装计时器开始，而非窗口创建的严格墙钟期限。浏览器拒绝 window.close 的情况也不能仅凭 DOM 测试排除。真实浏览器的自然 worker 休眠及窗口关闭效果仍须独立验收。

历史基线验证（不代表本次整合验证）：105/105 定向 Vitest 测试通过，三个改动模块的 statements/branches/functions/lines 均为 100%；测试归类审计通过。vue-tsc 初次因默认 2 GiB 堆上限退出，保持源码不变并使用 4 GiB 堆后通过。Chrome MV3、Firefox MV2 构建及 manifest verifier 通过。上述为本地固定 main 基线的测试，不代替 PR 最新提交的 CI 或真实浏览器验收。
