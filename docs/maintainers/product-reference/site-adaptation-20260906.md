# 网站适配

第一次使用请先阅读[自定义网站适配教程](/guide/custom-site-rules)。本页提供字段与运行行为参考；向内置目录新增或修改规则，请参见[贡献指南](/contributing/site-adaptation)。

网站适配用一份 JSON 说明：哪些网址使用规则、哪里是正文、哪些区域保持原文，以及哪些非正文更新无需重新扫描。全文与悬浮翻译共用这些规则。

打开 **设置 → 网站规则 → 网站适配**。内置规则默认开启，可以按名称或域名搜索、停用单条规则，或查看并复制到自定义草稿。未匹配的网站继续使用通用正文识别。

## 为一个网站添加规则

先在浏览器开发者工具中确认正文的稳定结构，优先使用 `article`、`main`、语义属性和稳定的内容类名。避免依赖自动生成的类名、列表序号或整页 `body`。

下面的包适用于 `example.com` 及其子域的文章页面，保留按钮、代码与作者信息：

```json
{
  "version": 1,
  "rules": [
    {
      "id": "example-articles",
      "name": "示例网站文章",
      "match": {
        "hosts": ["*.example.com"],
        "paths": ["/articles/*"],
        "excludePaths": ["/articles/editor/*"]
      },
      "mode": "focus",
      "content": [
        {
          "css": ["article p", "article h1", "article h2", "article li"],
          "resolve": "closest"
        }
      ],
      "protect": ["button", "pre", "code", ".author"],
      "exclude": ["nav", "[contenteditable]"],
      "watchIgnore": [".view-count"]
    }
  ]
}
```

粘贴到 **JSON 编辑草稿**，点击 **保存规则**。错误会显示字段路径；无效草稿不会覆盖已保存的规则。导入文件先进入草稿，检查后再保存。导出只包含网站适配包，不包含翻译服务配置或密钥。

**网址匹配预览**只检查已保存规则是否匹配网址，不会打开或读取这个网页。它不能证明选择器在该网站当前版本上存在。

规则修改会通过现有配置同步到已打开的网页。正在进行的翻译会取消并恢复原文，请重新触发翻译以使用新的范围。

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `version` | 当前为 `1`，不接受其他版本 |
| `rules` | 网站规则数组，每条 `id` 唯一 |
| `profiles` | 可选的结构模板；只允许一层引用 |
| `id` / `name` | 稳定标识 / 在设置中显示的名称 |
| `match.hosts` | 精确域名，或 `*.example.com` 表示根域及子域 |
| `match.paths` | 可选路径白名单，省略表示全部路径 |
| `match.excludePaths` | 路径排除列表，优先于白名单 |
| `profile` | 引用本规则包内的一份结构模板 |
| `mode` | `augment` 补充通用识别；`focus` 仅接受显式正文目标 |
| `content[].css` | 标准 CSS 选择器数组 |
| `content[].resolve` | `self` 仅匹配节点自身；`closest` 将其后代解析到最近的匹配内容块 |
| `content[].atomic` | 默认 `true`，将匹配区域作为一个候选；`false` 允许继续发现内部明确的正文目标；在 `focus` 模式中应同时声明段落选择器 |
| `content[].key` | 可选的诊断名称，不参与匹配 |
| `protect` | 保留匹配区域及后代的原文，包括外层正文里的嵌套区域 |
| `exclude` | 保留原文并裁剪正文扫描，适合编辑器或播放器等完整子树 |
| `omit` | 元数据保持原文，不参与扫描或翻译请求，也不复制到新增的双语译文中；不会删除网页原节点 |
| `literalLabels` | 限定需要检查的标签范围。仅当首个非空节点为 `b`/`i` 中的命令式标识符（或逗号分隔列表）、其余文字只在平衡括号中时，才保护、裁剪并从译文副本省略；完整说明句继续翻译，不使用命令关键词表 |
| `literalTokens` | 仅保护匹配区域中符合上述标识符形态的文字，继续保留在译文骨架；同一范围内的完整粗体句子或中文说明不会因此被保护 |
| `watchIgnore` | 只忽略该区域的动态变化；不会自动保护其中的文字 |
| `priority` | 数值较大者先提供正文目标；相同数值按声明顺序 |

域名按标签边界匹配：`example.com.evil.test` 不会命中 `*.example.com`。仅 HTTP/HTTPS 网址参与匹配；路径大小写敏感，`*` 匹配任意字符，其他字符均按字面处理，不支持正则表达式。查询参数和 URL 的 `#fragment` 不参与路径匹配。

CSS 选择器遵循浏览器语义，无效选择器会在设置保存时报告。标准选择器不能跨越 Shadow DOM 边界；引擎会分别发现可访问的开放根，关闭的根与跨域 frame 仍需要专门的运行时能力。[CSS 选择器参考](https://developer.mozilla.org/en-US/docs/Web/API/Element/querySelectorAll)

例如技术标签、消息回执使用 `omit`，代码片段使用 `protect`，以便代码仍出现在译文的原文骨架中。`literalLabels` 适用于命令手册里紧邻解释的标签，应使用严格的章节与兄弟结构选择器；不要直接匹配整页的 `b` 或 `i`。命令式标识符只接受英文字母、数字、下划线、点、加减号和斜线，避免把普通粗体句子或中文说明误判为命令。括号内附注可以包含自然语言。字段在模板展开、导出、用户覆盖和停用中遵循相同规则。

## 复用结构模板

模板用于减少相同内容结构的重复配置，不包含域名，也不能引用其他模板：

```json
{
  "version": 1,
  "profiles": {
    "reading": {
      "mode": "augment",
      "content": [{"css": ["article p", "main h1"], "resolve": "closest"}],
      "protect": ["pre", "code", "button"]
    }
  },
  "rules": [
    {
      "id": "example-docs",
      "name": "示例文档",
      "profile": "reading",
      "match": {"hosts": ["docs.example.com"]},
      "protect": [".version-picker"]
    }
  ]
}
```

规则自己的 `mode` 覆盖模板的模式；正文与保护等数组按模板在前、规则在后追加并去重。自定义包只引用自己的模板。设置中的 **复制到自定义草稿** 会展开模板，因此复制结果可独立导出和编辑。

## 覆盖与冲突

同 ID 的自定义规则会**完整替换**内置规则，删除该自定义规则后恢复内置版本。停用 ID 同时作用于该 ID 的自定义替代项。关闭网站适配后使用通用正文识别，不等于禁用扩展；后者由网站规则里的禁用名单控制。

不同 ID 同时命中时，正文目标按优先级决定，但所有规则的保护区域共同生效。任何命中的 `focus` 规则都会关闭通用候选回退。提高 `priority` 不能绕开另一条规则的保护或 `focus`；需要修改、替换或停用产生限制的规则。

引擎仍然保护输入框、代码、显式禁止翻译的内容及扩展自身节点。JSON 不能执行脚本、注入样式、移除网站节点、改写请求或关闭这些底层防线。

## 维护与验证

内置目录由三部分组成：经过现有回归验证的专用站点规则、按类别编写的站点规则，以及可复用的语义模板。规则随扩展版本分发，不下载或执行远程规则脚本。

- `src/core/site-adaptation/catalog/established.json`：已有专用规则及回归边界。
- `src/core/site-adaptation/catalog/websites.json`：扩展的网站目录。
- `src/core/site-adaptation/catalog/profiles.json`：共享结构模板。
- `src/core/site-adaptation/catalog/coverage.json`：规则类别、验证范围和能力限制。

开发者运行 `node scripts/export-site-rule-pack.mjs`，即可从生产目录生成完整的 `.output/site-rule-pack.json`，也可传入输出路径。生成包使用同一版本格式，可直接导入自定义草稿；保存后，同 ID 项会固定为自定义版本，后续内置更新需删除对应自定义项后才能生效。

规则条数、域名数与实站验证数是不同指标。语义模板夹具证明结构契约可执行；单站夹具证明指定结构的内容边界；只有实站浏览器结果才证明测试时页面实际可用。站点可能改版，目录不代表所有页面均经过实时验证。

新增或调整规则时，应验证：网址命中与排除、正文与保护区、悬浮和全文的一致性、翻译—恢复—再翻译、动态新增内容、路由变化以及规则更新后的迟到请求。不要把整个文章容器设为原子块来解决漏译，否则容易把多个段落合并。`focus` 模式应优先声明内部段落、标题等目标，并将非原子容器作为直接文字的后备；混合布局的段落与前后直接文字会分别处理。

字幕下载、图片 OCR、PDF、Canvas、关闭的 Shadow DOM 与新的跨域 frame 接入属于独立能力，不能靠增加正文选择器获得。网站上的可读 HTML 正文仍可使用本规则体系；专项能力应通过各自模块实现。

## 编辑器与输入限制

可下载 [JSON Schema](/site-rule-pack.schema.json) 配置编辑器校验与补全。规则包最大 2 MB、最多 2,000 条规则和 100 份模板；每个选择器列表最多 128 项，单个选择器最多 1,024 个字符。未知字段、重复 ID、未知模板和不符合要求的域名会被拒绝。具体错误以设置页校验结果为准。
