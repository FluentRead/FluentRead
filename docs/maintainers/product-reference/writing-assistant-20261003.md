# 写作助手

写作助手帮助你根据当前讨论起草回复，完善已有草稿，再按要求调整表达。功能默认开启，自动在 Gmail 邮件编辑器、GitHub 新建 Issue 页面，以及 Issue、Pull Request 回复区（包括首条回复）显示入口。其他网站、GitHub 仓库首页和列表页不显示入口。

完整设置的「工具与学习 → 写作助手」只有一个功能总开关，另提供写作偏好，以及 AI 服务、模型和服务连接配置。「写作服务」位于「回答风格」之前，用紧凑的双列布局集中设置 AI 服务、模型、输出语言与对照语言，窄屏自动改为单列。模型明确显示「跟随服务模型」或自己指定的模型；选择不支持写作的默认服务、未选择模型或未填写必要密钥时，设置页和网页卡片给出同一条配置提示，不发送无效请求。「回答风格」直接显示长度、风格、语气和「您的角色」四组选项，点击选项即可保存，与写作卡片使用同一份持久化设置。设置页调整影响后续生成，不会请求 AI 或改写当前版本。桌面宽屏将四组风格选项与表达示例并排展示，窄屏中示例跟随选项显示。关闭写作助手仍保留全部偏好；插件暂停时说明恢复插件即可继续使用。写作服务可以与网页翻译分别选择；微软、谷歌等机器翻译服务不能用于写作。不另设网页入口开关或写作快捷键。网页按钮右侧的「⋮」可选择本次关闭、当前网站禁用或永久禁用。选择后点击「保存」生效，「取消」不改变设置。本次关闭仅影响当前文档，刷新或再次打开后恢复；网站禁用只影响写作助手，可在写作设置的已禁用网站列表中重新启用；永久禁用可通过写作助手总开关恢复。插件总开关与全局网站禁用规则仍然有效；升级时保留用户明确关闭写作助手的选择。

设置页的「表达效果预览」随长度、风格、语气和角色变化，方便比较表达差别。示例不请求 AI、不读取网页、不消耗模型额度；自定义偏好会在实际生成时生效，示例会说明这一点。

网页入口和卡片使用 FluentRead 品牌图标，完整设置的侧栏沿用普通功能图标。Popup 不提供独立写作入口。卡片贴着当前回复入口展开，滚动和调整窗口时跟随定位；打开时根据空间选择展开方向，保持在屏幕内。卡片默认宽 640px、高 600px，窄屏自动适配；标题、语言与工具栏紧凑排列，正文保持原有字号并占据主要阅读空间。改写输入平时为一行，聚焦或有内容时展开。卡片高度与本次展开方向固定，草稿、参考内容、回答风格与语言选择在同一区域切换，长内容在卡片内滚动。右上角的设置按钮沿用线性图标风格。

网页入口显示在当前评论或发送按钮旁的空白处，不挤动网页原有按钮。空间较窄时收为品牌图标，悬停可查看用途；两侧都没有足够空位时暂时隐藏，空间恢复后重新显示。输入框调整大小或页面重新排版时，入口与卡片一起跟随。切换预览、隐藏或关闭编辑器、滚动到操作区不可见的位置时，会收起入口与卡片；多回复框的入口各自对应原编辑器。

点击「写作助手」后，已有草稿会自动进入完善流程；空草稿有当前讨论时自动起草回复；新邮件没有参考内容时，先在底部写下收件人、目的和要点，再点击「生成」。也可点「感谢与跟进」「说明进展」「礼貌婉拒」填入方向，填入本身不会请求 AI。输入区的 Enter 用于换行，⌘/Ctrl + Enter 用于生成；不会触发网页的发送操作。未选择支持写作的 AI 服务时，卡片提供「设置写作服务」入口；缺少模型或连接配置时按提示完成设置。卡片右上角也可打开写作设置。

「插入回复」默认只插入回复正文。右侧下拉菜单提供「插入双语回复」，按“回复正文、空行、对照译文”的顺序插入；没有可直接插入的编辑器时提供「复制双语回复」。请先选定与回复语言不同的对照语言，只有当前正文对应的对照译文完整生成后才可双语插入。修改正文或语言后，需要等待新的对照完成。Gmail 双语回复转换为可读纯文本，GitHub 保留 Markdown；均由你检查后手动发送。

输出语言默认「跟随目标语言」，使用你在 FluentRead 中设置的翻译目标语言；卡片显示实际输出语言。点击语言入口，可以搜索并选择其他语言，也可以恢复跟随目标语言。语言选择会保存；已有正文时，切换到不同选项会按新语言改写当前正文。旧版的自动语言偏好迁移为跟随目标语言，已选定的具体语言继续保留。

默认回复长度为「简短」，语气为「自然」，风格与角色为「自动」。点击下方「回答风格」，集中选择长度、风格、语气和「您的角色」；语气与角色支持预设和自定义。选择过程中不会请求 AI。确认「应用并改写」后，保存这些偏好并根据当前正文发起一次改写；尚无正文时，有可用参考或要点则「应用并起草」，没有内容则只「应用」偏好。点击「取消」或「返回草稿」放弃本次未应用的选择。Escape 先返回草稿，再按一次才关闭卡片。未改变任何偏好时显示「应用」，返回草稿而不重复请求模型。设置页也提供同样的预设和自定义输入；设置页自定义内容留空时，语气回到「自然」、角色回到「自动」（不指定回复身份）。角色会影响回应重点与表达立场：维护者关注项目反馈与协调，开发者关注技术排查，用户关注使用影响，客服关注操作帮助；同事侧重协作，领导侧重目标与决策，下属侧重情况汇报与所需支持。切换角色并应用后，会保留当前正文中的事实和手工补充，重新组织符合新身份的回复，不只替换措辞。角色不能代替事实或授权，也不应让 AI 编造承诺。翻译、精简和总结仍保留原文立场，不因角色选择改变事实或额外加入处理意愿。

明确选择开发者或维护者身份并回复反馈时，回复应先简短感谢反馈或贡献，再回应具体问题，必要时表达继续排查或协助支持的意愿，避免空洞的客服套话。不能据此声称已经复现或修复，也不应承诺完成日期。其他角色与自动身份不套用开发者口吻。

「参考内容」展示当前编辑器对应的信息和原草稿。GitHub 新建 Issue 时读取当前表单的项目和已填写标题；回复时包含当前项目、Issue/PR 编号和可见标题，并结合原帖与最近讨论；PR 行内回复使用当前评审线程，不混入其他线程。可见状态与发起人也会作为辅助信息。Gmail 使用当前邮件会话或撰写窗口中的可见主题与邮件正文。标题单独保留预算，参考信息总计最多 12,000 字符；有后续讨论时，原帖最多占 4,000 字符，余量优先保留最近回复。不读取隐藏内容、侧栏或其他页面，也不访问帖子中的链接。

生成时，写作助手可以按需重新读取本次「参考内容」，并在需要时查询你主动保存的学习记忆。记忆沿用翻译卡片的「学习记忆」开关，在学习中心管理；关闭时和隐私窗口中不会读取。启用后，相关记忆可能发送给所选 AI 服务，作为本轮写作的参考，不覆盖你选择的语言、角色或本轮要求。写作助手不会自动保存草稿或邮件到学习记忆。修改、删除或清空记忆会停止当前生成；可以重新生成以使用更新后的内容。

切换语言与生成对照译文时，只忠实翻译当前草稿，不查询记忆或调用参考工具。其他写作任务的工具调用也仅限本次参考内容与已保存记忆，不访问链接、不操作网页。结合参考资料生成回复时，可能需要多次 AI 请求，用量统一计入「写作助手」。

原有草稿最多 12,000 字符且只读。「项目与讨论」可删改，核对后点击「重新起草」，从原有草稿与更新后的参考信息重新生成；直接返回草稿会放弃尚未应用的参考修改。正文默认以 Markdown 预览呈现，点击「编辑正文」切换到原文编辑，完成后返回预览。预览支持标题、段落、列表、引用、代码和简单表格，以及粗体、斜体与行内代码；HTML 按字面文本显示，链接和图片不会被执行或加载。这是有限的 Markdown 子集，不保证完整 GitHub Markdown 排版。

生成后可以复制、重新生成，或在底部输入改进要求。改写以当前正文为基础，包含你对正文的手工修改。调整期间保留上一稿，成功后显示新版本；失败或停止时仍可继续使用已有草稿。重试保留上一次请求的任务类型、语言、参考内容和要求，翻译失败后仍忠实翻译；不会把未经编辑的半成品当成新草稿。如果你手工补写了保留的正文，重试会采用补写后的草稿，并继续保留原任务和语言。首次生成中断时保留收到的正文，并明确提示这版尚未完整；尚未收到正文就停止时，可补充要点或重新生成。卡片保留本页会话最近五个版本，同一编辑器和原草稿未变化时，关闭再打开会恢复当前结果。

点击「插入回复」只填写原编辑框，随后收起卡片并返回回复框，发送仍由你自己完成。GitHub 插入和复制保留 Markdown 原文；Gmail 插入和复制使用可读纯文本，去掉标题、强调等显示语法，保留段落、列表、代码、表格文本和链接地址。如果原草稿已改变、编辑器已关闭或页面已经切换，则保留网页原内容并提示手动复制。原草稿含链接、图片等复杂格式时，主操作为「复制回复」，保留原有格式。

「停止」、关闭卡片、离开页面或停用功能都会取消当前请求；迟到的结果不能覆盖新内容。草稿与参考内容只在本页会话中保留，开始起草或调整时发送给所选 AI 服务；自动显示入口本身不会调用 AI。模型用量中将这些调用归类为「写作助手」。写作助手不会自动发送邮件或提交评论。

MiniMax 模型列表新增 `MiniMax-M3` 与 `MiniMax-M3.1`，网页翻译和写作助手共用这份目录，已有默认模型保持不变。
