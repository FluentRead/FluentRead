## 目标与当前判断

建立能够回答两个问题的网页翻译基准：不同翻译系统在真实网页和不同内容类型上有什么质量差异；FluentRead 的分段、术语、上下文和文档理解流程分别带来了什么收益与代价。

首轮暂按英语 → 简体中文规划，沿用现有语料最密集的方向。模型比较要区分两种对象：

- **服务基准**：比较 Google、Microsoft 等黑盒翻译服务。服务内部模型可能不可见或会变化，结果按服务 ID、端点和运行日期标记。
- **模型基准**：比较可明确识别的模型 ID/版本及其配置。只记录 provider 名称不能代表模型身份。

两种基准都要和 FluentRead 的**完整产品流程**分开。完整流程还包括候选提取、分段、术语保护、上下文、缓存/回退、页面还原与错误处理；它测的是用户拿到的结果，不能单独解释某个底层模型的能力。

## 基准数据设计

### 样本单位

网页样本以**页面**为文档单位，保存可重复读取的正文快照和结构；评测样本可下钻到段落、句子或结构块，但模型排名和不确定性按页面/文档聚合，不能把同一篇文章切出的几十句话当成几十篇独立证据。论文和技术文档保留章节、表格、列表、代码、公式、引用关系；漫画保留整页图像、气泡区域、阅读顺序与气泡文本。

### 数据分层

把数据分成三套，分别报告：

1. **稳定回归集**：合成样本与受控反例，用来捕获否定、漏译、代码标识符、数字单位和分段边界回归；不用于推断真实用户体验。
2. **人工核验集**：有出处、许可和双语审核的真实公开内容，覆盖网页、科技论文、技术文档、漫画。它是模型排名与人类偏好的依据。对漫画先使用自有原创或明确授权图像。
3. **挑战集**：术语歧义、跨段指代、跨章节复现、表格/公式、动态网页、OCR噪声、气泡顺序、字数限制等稀有高风险情境。用于定位能力边界，不与自然分布混合计算总体表现。

按**源文档/网站/作品**切分开发集与留出集，禁止同一文档的相邻段落跨集合。每条真实样本记录：稳定 ID、文档 ID、语言方向、内容类型和子类型、原文结构/位置、获取日期、内容哈希、原始链接或作品标识、摘录位置、许可依据、审核状态、上下文范围及适用术语。图片还要记录页面/气泡区域和图像哈希。缺少授权或可追溯来源的样本不得进入公开基准。

每次模型运行单独记录：provider、明确的模型 ID 与版本（不可见时标 `opaque`）、端点、运行时间、语言方向、提示词/配置哈希、分段器版本、上下文策略、术语库版本或哈希、产品构建版本、输出、每段状态、重试/失败、延迟和可得的实际费用。禁止写入 API 密钥、用户网页、浏览器配置或个人令牌。

参考译文允许多个合理版本，并标注审核来源。机器生成的建议译文只能帮助准备审核，不能标成 gold；每个语义标签都要有实际审核人、证据、时间和仲裁状态。模型或裁判模型不能给自己签署人工审核。

## 评估体系

### 主结果与诊断结果

不做跨轨道单一总分。每个轨道至少报告：

- **盲审成对偏好**：同一来源文档、同一输入条件下随机排列系统输出，支持平局；按文档汇总偏好和区间，另报语言自然度、含义准确、术语和风格偏好。
- **错误标注**：以 MQM/错误跨度标注为参考框架，记录源文与译文位置、错误类别、严重程度和审核人；分别报告 critical/major/minor 与漏译、增译、错译、术语、语法、格式等类别。先报告原始类别和分母，不先定未经校准的权重分。
- **关键事实门槛**：关键否定、数值/单位、API/代码、公式和强制术语的错误率与文档级失败数单独显示，不允许被流畅度平均掉。
- **自然度与可读性**：在完整上下文中由目标语言读者评估，和语义准确分开。
- **任务结构指标**：根据轨道表格报告覆盖、结构保真、对齐、OCR 和排版结果。
- **运行指标**：成功/失败/延迟/费用独立显示；服务不可用不是译文语义错误，低延迟也不抵消质量风险。

人工打分维度、错误类型、严重度、盲审、双审和仲裁字段见[翻译基准人工标注指南](./translation-benchmark-annotation.md)。先用小批试标校准标签和评审分歧，再冻结版本扩数据；未经审核的模型输出不能进入金标准。

自动指标（如词面指标、COMET 类模型或 LLM 裁判）只作大规模筛查、排序线索或错误候选定位。先在本项目的人工审核集上检验它们对人类判断的相关性和错误类型召回，再决定是否用于扩展评测；不能用裁判模型分数代替人工标签。模型对比采用同一留出文档上的配对结果和文档级区间，按内容轨道、语言方向和难度分层。运行量不足时显示“证据不足”，不强行排名。

### 术语、记忆和上下文实验

使用匹配样本做消融，并固定底层模型和其他处理步骤：

1. 无文档上下文 vs. 当前产品可提供的邻段/章节上下文。
2. 无术语库 vs. 已审核术语库；再拆分“给定词条”与“系统从双语样例中发现词条”。
3. 无记忆 vs. 文档级术语/译法记忆；只对同一词义的重复项评分，允许语法、语域和语境要求下的合理变化。

## 产品设计方向

- **用户选择任务模式**：网页阅读、论文阅读、技术文档、漫画阅读分别展示适合的上下文和格式选项。默认网页流程维持轻量；论文模式强调章节/公式/引用，技术模式强调版本词库和标识符，漫画模式把 OCR 与译文排版状态一起呈现。
- **记忆范围清楚可见**：区分全局术语库、网站/领域词库、项目或文档词表、当前会话上下文、个人校订。显示何种记忆影响了译文，并允许用户预览、批准、禁用和删除；未经确认的单次改写不自动扩散成永久偏好。
- **单段与批次采用不同返回合同**：单段请求可以通过本地请求记录关联目标，模型直接返回译文文本，减少模型回显 ID/JSON 的格式失败；多段批次仍要求准确回传 ID 集合并逐项校验，失败时保留原文和原始响应。跨三轨的 36 格单段纯文本探针为 36/36 非空、36/36 符合预设文本形状；配对 JSON/ID 基线严格合同为 11/36，另有 23 个仅属离线分隔符修复候选。该结果只支持请求/响应结构的产品假设，不能说明译文准确或完整。[契约对照摘要](../../../workspace-data/evidence/translation-document-context-cross-track-bilibili-api-20261115/single-text-contract-v1/summary.md)
- **人机协作审阅**：审阅页并排展示原文、完整上下文、不同模型译文和定位到原文的错误跨度；保留“无法判断”和“合理变体”，可记录审核证据与仲裁。先服务维护者评测和人工校订，不把研究型总分塞进日常阅读界面。
- **反馈只进入用户控制的记忆**：复用现有本地校订和术语能力；新增长期记忆前给出范围、解释与撤销入口。基准采样与分析不得暗中上传阅读网页或校订内容。

### 对应的产品实验

1. **模式识别与人工改选**：以同一文档运行“用户选择模式”和“系统建议模式”，观察误分类、改选率、翻译完成率及评审质量；模式建议不得自动增加发给服务的正文范围。
2. **术语记忆的来源与作用域**：固定模型、源文和上下文，比较无术语、明确选用的词库、当前材料内确认译法、项目级确认译法。保存检索候选、适用词义、命中机会、正确采用、错误命中和过度统一；不同词义不得用字符串一致性替代人工判断。
3. **篇章一致性与文档理解**：按文档比较无上下文、邻段、章节定义、用户确认译法、章节摘要等逐档方案。测量指代和定义是否正确复用、前后结论是否一致、跨章节术语是否稳定，也检查旧机器译文传播错误、无关上下文污染和长文覆盖损失。
4. **用户控制与信任**：测量用户能否看懂本次请求使用了哪些记忆，能否改选范围、撤销误保存、隔离不同论文/项目；不采集网页正文或个人校订文本作为默认遥测。
5. **漫画区域路由与专属文本**：在人工核验的源语言、区域类别和阅读顺序上，配对比较全区域翻译、已知目标语言本地保留及不确定区域交由用户确认。报告误路由 / 漏路由、非目标区域盲审质量、完整页重组、API 区域项与 token 用量；ruby、拟声词和人物 / 作品专名需分别决定保留、翻译、隐藏或用户选择。当前四页探针只提供候选标签下的直通与重组信号，需先人工审定标签和 ruby 规则，再评估真实产品质量。[逐次结果](../../../workspace-data/evidence/translation-benchmark-manga-mixed-language-routing-bilibili-api-20261115/evaluated-results.json)
6. **漫画批次结构与上下文消融**：逐区域与整页批次分别测 ID/字段有效率、失败回退、完整重组、调用数、token 和延迟。原创 fixture 的 174 个上下文请求通过输入隔离检查，结构从基线 166/174 到上下文 174/174、配对措辞变化 79/166；UNESCO 两部作品的三批文本矩阵已按作品聚类汇总：无上下文 74/168、有同页文本 92/168，但《Nzinga》43/114→61/114、《Wangari》31/54→31/54。共有 68 个双侧有效译文对，48 个字串不同；同页上下文多用 12,737 tokens。新增一页多漫画海报用 3 种范围比较无上下文、同漫画和海报所选上下文：414/414 HTTP 200、输入隔离 414/414，严格结构 101/138、89/138、84/138，海报上下文 token 比无上下文高 157.6%。这些源文和调用嵌套在一个作品组，均是结构/成本/字面观察；不作语义质量结论。下一步按用户安排双语盲审，核对源文、区域类别、阅读顺序、准确度、语气、术语和跨区域一致性，再判断上下文收益是否值得成本。图像未上传；OCR、视觉和排版必须另设输入条件。[跨作品汇总](../../../workspace-data/evidence/translation-benchmark-manga-context-cross-work-20261115/summary.md) · [海报试验](../../../workspace-data/evidence/translation-benchmark-reliable-sources-comic-poster-bilibili-api-20261115/summary.md) · [v8 challenge](../../../workspace-data/evidence/translation-benchmark-manga-structure-context-bilibili-api-20261115/challenge-manifest-summary-v8.md)

每项实验只改变指定因素并固定文档版本、分段器、底层模型、提示和回退策略；源文文档是统计单位。质量、结构、运行可靠性、延迟/成本和用户控制分别报告。用户采用率不能替代语义标签，术语字符串命中率也不能代替正确译法率。

## 推荐实施顺序

1. **冻结当前基线**：保留 v2 合成集与历史报告原样；按[数据来源登记](./translation-benchmark-data-sources.md)先通过来源、许可范围、共同版本、双语对齐和人工审核门槛，再为真实评测启用独立版本/目录。
2. **做小规模人工试标**：优先英语 → 简体中文，网页、论文、技术文档各建立可追溯样本；漫画使用单独的图文数据和排版审查流程。先验证标注指南、审核用时、分歧和仲裁，再扩样。
3. **验证评分器**：用人工集比较自动规则、神经指标和 LLM 裁判；按领域/错误类别检查漏报和错报，不以论文中的通用排名替代本地验证。
4. **运行匹配的模型基准**：明确挑选可用的服务/API、版本与模型；固定输入和产品路径，先做小样本成本/可用性演练，再扩大到留出集。每个运行保存报告快照。
5. **完成产品消融**：独立估计分段、术语、上下文和文档理解的质量增益与性能代价；将证据转成内容模式和记忆控制的产品决策。

在取得人工基线和重复运行数据前不设“质量提升 X%”目标，也不因单轮匿名服务结果改变产品默认服务排序。

## 外部研究依据

- WMT24 Metrics Shared Task 使用 MQM 人类评审和专门的对比挑战集，并按系统级与片段级配对准确率评估指标：[Freitag et al., 2024](https://aclanthology.org/2024.wmt-1.2/)。
- FLORES-200 为 `eng_Latn` / `zho_Hans` 提供句级人工参考，Meta 官方仓库列明 FLORES-200 为 CC BY-SA 4.0；WMT25 同时指出它对现代 MT 已偏旧。因此本项目只把它当作参考指标/格式校准集。SacreBLEU 2.6.0 明确 `chrF++` 使用 word order 2，并提供中文 `zh` BLEU tokenizer；每次运行应保存完整 signature：[FLORES-200 README](https://github.com/facebookresearch/flores/tree/main/flores200) · [WMT25 开发数据建议](https://www2.statmt.org/wmt25/translation-task.html) · [SacreBLEU metric 配置](https://github.com/mjpost/sacreBLEU/blob/master/README.md#scoring)。
- WMT25 General MT 的人评 JSONL 保留系统分数、错误跨度与文档 ID，并包含英语 → 简体中文；官方数据授权研究用途，需遵守具体源数据引用要求。`tgt_text` 里存在 `refA`，但人评数据 README 未说明该键的映射；本项目参照 WMT 论文说明的人工参考数据，把它暂作参考候选并做探索性指标 meta-eval。chrF++ / BLEU 对 WMT 人评分数的片段偏好准确率约 0.55，系统级 Spearman 约 0.34；这些结果不足以将指标视作已校准，也不能混入 FluentRead 直接系统排名。参考身份待组织方确认，单参考与片段/文档评估单位不一致也是限制：[任务及许可说明](https://www2.statmt.org/wmt25/translation-task.html) · [人评数据 schema](https://github.com/wmt-conference/wmt25-general-mt) · [WMT25 findings paper](https://aclanthology.org/2025.wmt-1.22/) · [人评校准](../../../workspace-data/evidence/translation-benchmark-wmt25-human-calibration-20261114/summary.md) · [指标复评](../../../workspace-data/evidence/translation-benchmark-wmt25-metric-meta-eval-20261114/summary.md)。
- WMT25 findings paper 说明主要语种采用 ESA，将 Direct Assessment 与错误跨度组合，并在文档级来源上做评估。我们对其英→简中数据的派生聚合显示人工评分的差异与错误跨度总体负相关，但评审者差异和领域差异不小；保留独立维度、双审、仲裁，不把单一 DA 数值当无误差真值：[Kocmi et al., 2025](https://aclanthology.org/2025.wmt-1.22/) · [分析摘要](../../../workspace-data/evidence/translation-benchmark-wmt25-human-calibration-20261114/summary.md)。
- WMT25 Terminology 把 no / proper / random terminology 消融，与总体质量、术语成功率、文档内一致性分开；其公开仓库按 CC BY-NC 4.0 发布，语言方向包括传统中文金融文档但没有英语 → 简体中文。此处只引用方法，不导入数据：[官方任务说明](https://www2.statmt.org/wmt25/terminology.html) · [仓库许可与指标](https://github.com/wmt-conference/wmt25-terminology)。
- COMET 使用源文、候选译文和参考译文预测人类判断，可作为待校准的自动指标候选：[Rei et al., 2020](https://aclanthology.org/2020.emnlp-main.213/)。
- 文档级指标的对比挑战研究指出，现有指标的上下文敏感性与窗口大小有关；短窗口在其测试中更稳，但不能据此直接外推到 FluentRead 的中文网页：[Dahan et al., 2026](https://aclanthology.org/2026.eamt-1.19/)。
- WMT26 术语任务分别测试显式文档词典和从平行样例获取术语，并报告总体翻译质量与术语成功率；这两种能力应拆开测：[Charkiewicz et al., 2026](https://aclanthology.org/2026.wmt-main.51/)。
- 科学文档术语评估研究说明强制统一译法可能压制合理变体，因此一致性指标要考虑词义和语域：[Dahan et al., 2026](https://aclanthology.org/2026.amta-research.7/)。
- 漫画研究已用页面图像与气泡级译文研究视觉上下文，人工核验没有证明图像感知裁判普遍优于纯文本裁判：[Kimura & Suzuki, 2026](https://aclanthology.org/2026.wmt-main.20/)。漫画理解也开始把页内 OCR 与叙事问答分成独立基准任务：[Baek et al., 2026](https://aclanthology.org/2026.findings-eacl.284/)。
- 对 LLM 自动质量标注的最新跨语言研究发现，人与模型的审核一致性会随语言对、领域和标注方案变化；人工标签仍是本项目校准自动裁判的必要锚点：[Almaghout et al., 2026](https://aclanthology.org/2026.findings-emnlp.577/)。
