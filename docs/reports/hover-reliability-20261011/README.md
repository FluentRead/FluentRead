# 悬浮翻译性能与可靠性验证

悬浮延迟现在从进入真实候选开始计时，同段移动保持截止时间和配置快照，换段重新计时。连续移动按绘制帧合并，首点立即交给运行时，松开快捷键提交最后位置。译文和在途请求保持唯一，连续经过已译或失败段落不会反复切换或重试。

页面隐藏、离开视口、滚动、配置变化和路由切换会撤销过期的等待。路由切换同时取消旧请求域、释放旧 loading，下一次手势可以立即使用新请求域；旧响应仍受状态、来源和路由代次校验。动态宿主替换后的明确悬浮请求不会再进入没有重派队列的全文安静窗口；自动全文的正文安静窗口和持续变化计数保护保留。

可信鼠标点击也会记录坐标，支持内容脚本挂载后鼠标未移动就按快捷键。自定义快捷键复用核心解析器，包括字面量加号。划词仲裁、Mac 与 Windows 差异、长按、触摸、原生链接和输入保护均由原有入口处理。完全空闲的移动只记录位置和宿主交互，有手势或已交付工作时执行完整可用性检查；没有新增完成猜测或另一套生命周期。

共享运行时把停留调度提取到独立模块，配置变化接入手势已有订阅。整合最新 main 后，app content runtime 为 277 行，共享全文 runtime 为 2182 行（不含文件头），原架构上限没有调整。只读对照了参考项目的事件调度思路，实现沿用 FluentRead 的 WXT、Vue、TypeScript、候选和状态架构，未复制参考代码或引入跨仓库依赖，依赖及版本号保持不变。

## 性能采样

原始基线 `fe7005dd9` 和原始优化生产包各采样三次，每次每阶段执行 320 次真实移动。首轮运行八组场景，之后两轮只运行性能场景，使用相同夹具、事件路径、输入和链接。完整数据、范围和产物哈希见 [性能采样](./performance-repeats.json)；下列数据没有混入随后整合 main 的单轮行为回归。

| 阶段 | 基线脚本耗时中位数 | 修复后脚本耗时中位数 | 基线总任务耗时中位数 | 修复后总任务耗时中位数 |
| --- | ---: | ---: | ---: | ---: |
| 关闭悬浮的普通移动 | 10.973ms | 10.515ms | 160.238ms | 150.130ms |
| 开启悬浮的空闲移动 | 15.898ms | 17.155ms | 165.618ms | 165.500ms |
| 已译段落连续悬浮 | 292.769ms | 274.854ms | 511.340ms | 457.544ms |

连续悬浮的脚本与任务中位数分别降低 6.12% 和 10.52%，但样本范围明显重叠，不能推广为稳定的全站加速比例。空闲开启相对关闭的脚本增量中位数从 5.105ms 到 6.988ms，即每 320 次增加 1.883ms，约每次 5.88µs。针对完全空闲状态的快速路径已减少这部分检查；有工作时保留取消保护。所有 18 个采样阶段没有 long task、阻塞时间或布局，墙钟运行时间受 CDP 输入节奏影响，不能当作用户翻译延迟。

## 重现

先运行定向单元回归与 `pnpm compile`，构建生产包后执行：

```bash
node scripts/testing/run-hover-reliability-test.cjs \
  --extension-dir .output/chrome-mv3 --playwright-root <Node包目录> \
  --focus-safe-helper scripts/testing/focus-safe-browser.cjs \
  --artifacts-dir /private/tmp/fluentread-hover-reliability
```

追加 `--cases dom-replacement` 可检查动态来源；`--cases pointer-performance` 仅采样性能。`--baseline` 只用于旧产物，允许记录行为失败后继续采样，不能用于修复验收。
