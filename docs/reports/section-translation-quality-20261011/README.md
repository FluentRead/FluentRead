# 页面区域翻译性能与交互验证

本轮以页面区域局部翻译为主，保留“悬停预览 → 单击锁定 → 调整范围 → 显式确认”的交互。只改善 FluentRead 自身实现，没有引用或修改参考仓库，没有升级依赖、修改版本号、配置格式或扩展权限。

## 行为与架构

完整候选发现、状态盘点、位置测量和派发按最多 200 步或累计 8 毫秒分片，让浏览器继续绘制和处理输入；在途候选数受现有并发配置约束。视口内、下方、上方的阅读顺序不变，完整翻译仍发现全部候选。预览沿用 4,000 步的下限计数，不以删减实际翻译内容换取性能。

区域编排继续复用共享候选核心、`translateTarget`、请求会话、供应商队列、渲染器和恢复状态机。操作只记录本次候选的预期状态与来源身份；共享状态清除通知增加可选的旧状态参数，已有两个参数的订阅保持原行为。后来的悬浮翻译／恢复、另一区域接管及方案切换优先于旧任务，普通段落与合成行内段均沿用共享候选 key，包含前缀 Comment、Element 和 Text 的来源也能正确识别。

同一区域进行中再次确认“恢复原文”会停止剩余任务并恢复当前译文；退出运行时、全页恢复、导航或断开选区也会取消。取消无需等待供应商返回，只清理仍属于本操作的 loading 状态，迟到结果不重新插入。延迟派发前重新核对组合树边界，移到选区外的 light／Shadow DOM 来源保持原文。失败重试绕过失败缓存，已成功段落保留。

选择器会在布局、内容、保护属性及滚动变化时重新命中静止指针；锁定范围随内容移动，隐藏、移除或零尺寸目标解除锁定，确认时再次核对可见性。原文预览覆盖嵌套开放 Shadow DOM，避开译文和扩展界面；同一范围的控制条更新不重复读取正文。仍保留约 80 毫秒稳定窗与边界容差。入口卸载或被替代时释放监听器并取消任务，旧结果通知不会打断新的选择，异常可恢复后再次操作。

## 本机受控性能样本

独立导出基线 `fe7005dd9`，使用相同锁定依赖、生产 Chrome MV3 产物、隔离 Edge、相同 180 段／2,160 个行内节点与固定延迟的 Google 响应夹具。主对照见 [基线报告](./baseline-browser-performance.json)，最终性能样本见 [性能与布局报告](./browser-performance-layout-attempt.json)。探针从扩大到整个区域前开始，覆盖预览、确认和完成过程；首请求用 60 毫秒轮询观察，时间是观察上界。

| 指标 | 基线 | 候选 |
| --- | ---: | ---: |
| 大区域预览可确认 | 385.8 ms | 293.9 ms |
| 确认至观察到首请求 | 1,239.3 ms | 388.9 ms |
| 确认至观察到首译文 | 1,253.9 ms | 471.7 ms |
| 最大 rAF 帧间隔 | 533.3 ms | 17.7 ms |
| 最大 16 ms 计时器延迟 | 540.9 ms | 33.0 ms |
| 记录到的长任务（≥ 50 ms） | 1 次，545 ms | 0 次 |
| 全部 180 段完成 | 18,856.2 ms | 18,289.7 ms |
| 实际供应商并发峰值 | 1 | 1 |

两边都完成 180 个请求、保留 2,160 个原始行内节点、未翻译相邻区域；预览与锁定均不发请求。Google 仍遵循共享调度，并非把供应商并发提高到区域在途上限 4。此次变化主要改善主线程响应与首段出现速度，不把夹具耗时当作线上服务性能。

这是单次本机对照；后台构建、缓存和系统负载会影响计时。辅助的 [基线阶段样本](./baseline-phase-sample.json) 记录到 confirmed-region 阶段 592 ms 长任务，展示样本波动，未替换主对照。同步边界仍包括已有 owner 索引枚举、最终排序、单候选 DOM 读取和精确恢复，分片预算不能保证任何复杂宿主页面的单步操作都低于 8 ms。

## 验证与重现

完整清单、构建与浏览器范围见 [验证清单](./validation.json)。区域及入口生命周期 244 项、共享状态通知 105 项、油猴配置 23 项及架构 907 项均通过，共 1,279 项定向断言。四个区域模块的 [覆盖率](./coverage-summary.json) 在 statements／branches／functions／lines 均为 100%，没有降低阈值或新增忽略；该数字不包括整个共享 `state.ts`。共享状态通知的真实 DOM 测试验证恢复后旧 synthetic 来源仍可辨识；独立复审的扫描期恢复用例验证旧计划不重译，操作结束后订阅完全释放。架构测试中 894 项为中文源文件头断言，不能当作 894 个翻译场景；未运行全量回归。

浏览器 runner 的默认 core 范围保持不变；`--case-set quality` 增加 layout、nested-scroll、replacement、boundary、shadow、retry、cancel、performance、narrow 九组，`--quality-cases` 可只执行指定组。通过 `--project-root` 对独立基线执行相同生产构建新鲜度校验，没有绕过该校验。

首轮性能与布局通过后，嵌套滚动夹具因 `height:120px` 加上下 8px padding，实际高度为 136px，固定滚动 120px 后指针仍在 alpha 段落内，错误地期待 beta。报告保留该失败；修正为实际 `offsetHeight` 后只继续剩余组，没有重复测性能以挑选更好的数值。

第二轮动态与边界场景通过后，部分失败夹具把原生 Google 合批中的两个来源作为整批网络异常拒绝，却错误期待只失败一段；一般网络异常还触发端点冷却。该 [尝试报告](./browser-dynamic-boundary-attempt.json) 保留。最终部分失败场景单独关闭 Google 原生合批、并发设为 1，使用请求级 HTTP 400 受控失败，验证失败来源重试、成功来源保留。此场景不能当作原生批请求部分失败的协议验证。只继续剩余场景，失败归因与最终范围在验证清单中分别记录。

部分成功时的实际区域反馈是“翻译剩余 1 段”，测试原先错误期待“翻译此区域”；[断言修正前报告](./browser-retry-label-attempt.json) 保留。修正为剩余段落的准确反馈后，[最后三组](./browser-retry-cancel-narrow.json) 通过：仅再次请求失败源 1 次、保留成功译文；36 段处理中恢复，只有 2 次请求已经派发，迟到结果不重挂，之后可再次完整翻译；390px [浅色](./quality-06-narrow-light.png)／[深色](./quality-06-narrow-dark.png) 的扩大、缩小、重选、确认和关闭控件均可见，调整、重选与 Esc 均不发请求。各质量组通过证据分布于报告中，不能把存在失败的尝试报告描述为整次成功。

隔离浏览器使用临时 profile、第二屏正常可见后台窗口、`macos-background-cdp` 与 `launchservices-no-foreground`；原生 macOS 激活事件监视覆盖运行和关闭阶段，报告记录浏览器激活次数与 profile 清理。没有连接用户日常 profile、调用前台聚焦或系统鼠标操作。

一次 retry 等待期间，焦点保护检测到当前 CDP 浏览器进程进入前台并停止运行，临时 profile 已删除，见 [中断报告](./browser-focus-interrupted-attempt.json)。用户确认没有点测试窗口；当时 finally 在保存事件前断言失败，未落盘历史 PID 和事件时间线，因此无法确认触发原因。runner 已修复先保存监控摘要再断言，并增加仅留本机的逐动作／原生事件 JSONL；该私有诊断文件不提交。之后受控三组复测的浏览器原生激活数为 0，不能用它抹去之前的中断，也不宣称对所有环境绝对保证不抢焦点。

[核心与 GitHub 报告](./browser-core-github.json) 的 19 项验证通过，包括既有键盘、快捷键、方案切换、恢复和关闭交互。真实 GitHub README 区域内生成 27 个译文，区域外为 0，共 27 次夹具请求，见 [页面截图](./github-readme-translated.png)。该次未捕获页面异常为 0，控制台保留 1 条资源 HTTP 404；当时未捕获资源 URL，无法精确归因。

真实 GitHub 页面交互仍使用受控 Google 响应，不能证明线上翻译质量、鉴权或网络可靠性。Firefox 与油猴仅完成构建和静态验证；浏览器运行证据限定于本次 Edge 环境、所列页面与夹具。`console.error` 与未捕获页面异常分别记录，故意失败的请求日志不算“控制台零错误”。
