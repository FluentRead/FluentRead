## 圈选模型识图

`node scripts/testing/run-area-vision-test.cjs --extension-dir .output/chrome-mv3 --playwright-root <Node包目录> --focus-safe-helper <focus-safe-browser.cjs路径> --artifacts-dir /private/tmp/fluentread-area-vision` 使用生产扩展与临时 Edge profile，在后台可见窗口中验证识别方式及提示词保存、选区裁剪、无需 OCR 语言包的视觉路径、不支持或未知模型的 OCR 路径、模型能力覆盖、失败重试与取消清理。

该脚本的模型端点是本机 HTTP 夹具。它检查真实发出的图片尺寸、摘要及提示词，报告不保存图片请求体或凭据；截图展示真实扩展 UI。通过意味着请求和交互链路符合约定，不代表真实视觉模型对手写、模糊文字或复杂版面的识别准确率。

## 图片翻译完整流程

### 漫画顺序与文字边界的离线回归

`mangaReader` 与 `imageTranslationRuntime` 用确定性 DOM、布局帧和请求 gate 检查混合 IMG／Canvas／背景图片的顺序、重复或非法序号的稳定回退，以及布局变化通知到下一帧之间不启动过期任务。显式重试和开关仍读取最新布局，取消、暂停、释放与迟到结果的所有权断言保留。该范围不下载或加载识别模型，不证明公开漫画站点的真实 OCR 质量。

`imageOcrNormalization`、`mangaQuality` 和 `imageTranslationRendering` 保留韩文 Jamo、补充平面汉字及 IVS、半角浊音、组合字符与 emoji 的完整原文，并检查现代字素分割和缺少 `Intl.Segmenter` 时的窄框排版。后者只在确定安全的空格两侧分词，复杂无空白词组保持整体；英语组合字符、法语、俄语、泰语与老挝语的多词段落另检查字号，不能以整段缩字代替换行。纯 ASCII 与普通东亚文字仍保留原快路径。

`mangaViewWordBoundary` 与 `mangaOcr` 核对整页与气泡的两个已有拉丁识别视图：只有非空格字符完全一致、原图中稳定字形与明显间隔支持某一已有候选时才采用其文字，保留局部几何；透明、多墨色、纹理、连接字形或来源漂移均沿用原规则，不生成第三种文字。原图读取与既有方向、斜行预处理共用两百万像素，每页最多六十四次证明；不增加模型推理，已有颜色读回适配的预算与生命周期保持独立。测试覆盖原对象及 structured clone 绑定、去重后实际采用的来历、取消与失败计费，以及 `POSTCARD` 等不能偏好更多空格的反例。物理间隔只能约束已有候选，不保证语义词界。

`imageParagraphs` 对普通图片的续行和扫描早停使用同一整数源像素间距，避免缩放还原后的亚像素误差拆段；真实下一像素、不同字号、列表、遮挡与栏位仍阻止合并。离线回归包含冻结自然漫画的原坐标与原 PNG 局部像素，但不代替当前完整产品的原生 OCR 验收，也不覆盖漏字或真实大行距的质量缺口。

`imageParagraphGapEvidence` 复用已有普通 Paddle 识别视图的像素，检查同色封闭背景、两行之间的完整空白走廊与两侧局部图案，仅为唯一的实际相邻行提供布局关系。证据须沿 Worker 消息、实际文字采用与最终数组绑定；克隆、去重丢失、数字保护或其他文字遮挡均不能借此跨越。它只豁免行距，不放宽字号、方向、列表及完整段落对齐条件，不提供清字权限，也不增加 Canvas 读回或模型推理。三张便携源像素夹具覆盖五组对白和形似对白的独立控制标签；这是确定性回归，当前生产构建仍须另做原生验证。

`imageRuby` 核对日文小字的唯一归属、横排上方/竖排右侧位置、字号比例、遮挡、重复运行与比较预算；普通图片合段和漫画分组共用归属规则，正文及注音仍保留逐框清字范围。`mangaPatchResult` 验证注音余量使用自身字高，坐标复制后仍匹配；原文碰撞复用同一查询，避免注音合段后扩大清字或误判相邻原文冲突。`imageTranslationOffscreenRuntime` 验证注音不独立发送翻译、不重复绘字，并区分真正进入注音清字范围与仅进入正文字号余量的相邻原文。冻结彩色语料中的注音锚点仍保留：像素续行回放以正文和附属 `ruby` 记录共同核对源字符，不能把这些记录算作独立翻译请求。原生 runner 记录 `ruby`，旧的仅正文评分仍单独保留其结果，不为这项改动重写冻结源图或真值。

`imageTranslationRendering` 覆盖原文单行在参考字体中按墨迹宽高独立推算尺度的一致性、失效回退及 Canvas 状态恢复；最终文字仍按实际字体墨迹、描边和多行基线适配，单行不重复扣除 CSS 行高。`run-image-translation-flow-test.cjs --trace-typography` 仅用于标准确定性 48px Arial 原图，在离屏文档按需创建时观察真实 `fillText`，记录 OCR 框、源文字度量、实际绘字字体和原生 PNG；不重放受任务归属保护的离屏请求，不改生产文字或绘制函数。

`imageSourceAppearance` 验证同帧不透明底色、共同源字色、混色拒绝、注音分离、整段间隙和实际绘字范围；纯色源色采用未取整的局部亮度对比至少 4.5:1，参照 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。只读调色板不含修补 mask，宽灰块仍须被原擦除准入拒绝。单行新增高度至多每侧十二像素，全部新增像素须仍是同一不透明背景，并避开其他原文及已规划文字范围；整页像素与比较预算在采用样式前检查。普通图片流程测试核对实际绘制参数及原清字框，漫画普通绘制与绕孔位图均核对源色和细底色描边。字体 trace 另保存原始 PNG 和实际裁切框，用于核对新增像素。

独立的 `sourceInk` 仅为样式观察补充原框外四像素的实际抗锯齿尾缘和完整不透明渐变：四边与双线性背景逐像素相符，显著差异须在物理字框余量内，实际重复主墨色还须解释全部墨迹的共同覆盖率。渐变至少有四级真实颜色变化，量化误差容忍只限此只读观察；它不改变原擦除、透明保护或模型准入。渐变局部对比至少 3，并使用细对比描边，不把此门槛或缩放后的图片称为 WCAG 达标；不会提供纯色扩框权限。混色、纹理、透明和注音不明确时撤回。单项最多 65,536 像素、4,096 种墨色、128 个物理框，整页额外两遍观察面积和行框比较均在已有总额度中预付。真实回归同时核对原图色值、完整输出、非文字区域、耗时和模型请求，不能只看单元测试颜色断言。

`imageAlphaProtection` 以固定 RGBA 输入和受控 Canvas 像素端口验证普通图片的透明保护：确认完整背景边界后，保护比背景 alpha 更低的孔洞与半透明图案的全部 RGBA；修补不能写入这些像素，也不能把它们当作背景样本污染邻近底色。保护范围同时考虑修补采样上下文与绘字范围，包含物理行之间和绘字余量中的孔；真正擦字仍沿用原行框。排版须保留完整译文并避开保护区，不能最后套回原 alpha 平面而切掉译文字形。透明底允许在原本空白的位置绘制新的完整字形。

该回归覆盖 alpha 阶梯、固定半透明底色、孔外背景、封闭待修区域、未知外周、重叠区域、取消及失败后重试。不透明路径保留原整页读写和测宽，不为保护额外复制或读回整页；无法确认透明边界、没有可靠修补背景或全文无安全空间时，原子保留原图并在现有文字面板提供完整译文。这里的受控像素测试不证明真实字体栅格、PNG 预乘往返、OCR 或在线供应商质量，仍需相应原生回归证据。

`imageMatteRepair`、`imageMattePage` 和 `imageMatteAvailability` 检查严格透明准入失败后的完整 RGBA 修补。背景候选来自同帧原像素；必须由完整静区闭环、全部差异组件及共同颜色合成域确认，不能以主色比例或作者背景层直接放行。每一个待清墨迹像素还须处于同次实际 Paddle 检测位图，或下述可选同帧文字分割输出的两像素 Chebyshev 邻域；检测框包络或组件中单独一个锚点不足以授权整块颜色。alpha 与底色相同而 RGB 已被抗锯齿墨迹改变的像素仍须识别。连接观察域外缘的图案必须与原文字框及墨迹隔离；歧义、未归属碎片、多色拟合失败或穿出观察域均保留整张原图。

选定首个 canonical 有效共同端点后，再检查原 RGBA 墨迹的薄抗锯齿边：同一前向量化域中可达到九成前景 coverage 的像素作为近端核心，其余墨迹须处于该核心的两像素 Chebyshev 邻域。上界恰为九成但开区间的像素不作为核心；不为通过而穷举其他端点。最终 mask 暂作截断距离场，距离变换为两趟线性扫描；另有 mask 初始化、墨迹准入扫描及每个已计费颜色像素的一次 coverage 约束，不称为零额外 CPU。没有新增 ROI 数组或像素读回，不放宽原检测支持门。这项保守检查阻止黑字附近宽灰牌、渐变条及宽阴影被同一黑白颜色线吞入；无法证明薄边时仍保留原图和全文。相同形状的纯色图案与文字仍可能无法区分，模型前景及此颜色条件都不能作为语义保证。

可选 CTD 只补充普通图片模式的透明救援。先生成没有写入权限的整页提案并完成所有颜色、原文/数字、图案归属和完整译文字形预检；既有检测已覆盖时，不准备额外模型。不足时，只读取已导入的 `comictextdetector.pt.onnx`（94,669,756 字节，SHA-256 `1a86ace74961413cbd650002e7bb4dcec4980ffa21b2f19b86933372071d718f`），缺失不下载，也不改变普通 OCR 的就绪条件。可在现有离线模型入口导入，来源与权重使用条件由提供方决定，项目不捆绑权重或参考 GPL 实现。未知缓存、模型协议和执行错误保留首因，不能冒充缺失缓存。

仅当本次救援确实因缺少可选模型而保留原图时，结果标记为可在模型就绪后重试。用户再次翻译同一图片时先读取资源状态；仍未导入则复用已有文字，不重复 OCR 或文字翻译。导入后显式重试会重新执行当前图片；已生成的译图与其他安全回退不因资源状态检查而失效。此生命周期由真实缓存与页面运行时的确定性端口回归验证，不能代替原生浏览器的导入与重试验收。

`imageTextSegmentation` 在已有漫画 Worker 内执行固定白底 RGB、像素中心三角低通、逐轴整数舍入、右底黑色补齐及 `float32[1,3,1024,1024]` 构造；水平中间行仅保留当前垂直窗口。离屏主线程只用常数时间核对本帧 RGBA 的尺寸、完整视图与非共享缓冲，在实际 attempt 通过 `postMessage` 克隆像素快照，保留原图供绘字和 CPU 重试，不在主线程分配或扫描 12 MiB 张量。每次消息最多额外持有 64 MiB RGBA 快照；不使用 PNG 往返代替快照，以免半透明像素改变。Worker 验证同一像素边界及固定模型元数据，再构造张量和验证有限 `[0,1]` seg，先以 Float32 乘 255 截断成 1 MiB 自有字节并释放全部 ORT 输出，再按内容区逐轴投影、阈值 128 和源坐标两像素邻域提供支持；`det` 与 `blk` 不提供擦除权限。每页另限 128 次投影尝试、2,097,152 个源 ROI 像素、262,144 个位图字节及 16,777,216 次重采样系数工作，失败预留不退费；原全页颜色、绘字及上传预算不变。分割会话独立三分钟空闲释放，缺失缓存、预检失败及普通不透明成功路径不运行 CTD。显式数组预算不包含 ORT workspace，不能当作进程峰值内存或整页提速承诺。

`ocrWorkerRuntime` 的普通 Tesseract 识别在自身语言与参数串行队列内，再等待 Offscreen 共用的本地推理预算；预算满时不初始化识别 Worker。等待期间取消或销毁不启动 OCR、不占用后续槽位，也不终止其他本地模型；已开始识别仍按原规则清理并释放预算。`ocrWorkerRuntime` 回归覆盖跨模型等待、识别全程持槽、排队取消、销毁和失败后恢复。

`benchmark-image-worker.cjs` 用指定旧提交与当前 checkout 的真实客户端、Worker 处理器和像素算法，在隔离且不抢焦点的可见浏览器中执行交替 A/B。仅替换 ONNX 算子和模型缓存，核对完整模型输入与输出 SHA-256、原图未变、一次 CPU 回退和取消后恢复；记录主线程输入工厂至消息发送返回的连续阻塞、定时器延迟及受控总耗时。该测试不证明真实模型或整页速度。命令显式提供旧提交、证据目录、Playwright 包目录及与 `owned-browser-close.cjs` 匹配的焦点 helper：

```bash
node scripts/testing/run-resource-safe.mjs -- node scripts/testing/benchmark-image-worker.cjs \
  --before-ref <base-commit> --out-dir <evidence-directory> \
  --playwright-root <node-packages> --focus-safe-helper scripts/testing/focus-safe-browser.cjs
```

测试驱动仅在显式组合 `--preload-text-seg --model-cache-no-download` 时预载可选模型，沿用 `--model-cache-dir` 的固定 SHA 目录。浏览器启动前只读校验本次全部模型；缺失或损坏即失败，不创建锁、不修复文件、不下载。预载只导入 CacheStorage，不准备或运行分割会话；没有该 flag 的原 OCR 三文件路径不变。严格诊断仍要求 det/rec 创建记录；seg 未绑定时可缺省，一旦实际绑定就必须有成功创建记录，不能把缺少事件当作完整采集。创建错误与原焦点、资源、告警门禁保持。

独立回放用两张原 PNG 与历史缓存 seg 验证像素协议、九处完整字形及局部擦除。真实 Canvas 的 PNG 编码可改变保护区的 straight RGB 字节：报告必须分别保留原始字节差异、alpha 变化和明确公式的 premultiplied 比较，不能用少量探针或归一结果替代完整差异。历史输出回放不证明当前同帧模型推理、完整扩展运行、在线供应商或性能，仍须另外验收。

Canvas 在预乘与非预乘透明度之间转换有损，实际读回可能改变半透明颜色字节（[HTML 标准](https://html.spec.whatwg.org/multipage/canvas.html#pixel-manipulation)）。逆量化域仅在精确半整数读回边界兼容两侧相邻结果，不增加通用逐通道色差容忍；作者混合的前向 coverage 域仍下闭上开，全部像素仍须共享同一组端点。回归使用真实 Chrome 捕获的三个字面颜色样本，并保留半值反例、宽灰牌和多色拒绝。

颜色证明最多尝试 64 组整行共用的背景和前景端点；每组都对所有墨迹像素使用一致的前向量化域，不允许每个像素另选端点。全页共享 4,194,304 次候选像素检查，失败不退费。宽低透明度不确定域无法在预算内证明时保持原图，不能把所有颜色分别可行的宽区间冒充共同前景成立。灰底牌和低 alpha 红绿多色负控保留在回归中。

`imageDetectionEvidence` 只从既有原比例整页或整数瓦片检测捕获自有位图，不增加模型推理。位图按锁定 SDK 6.6 的实际 canvas-native 路径保存：概率先经 `Math.round(p*255)` 转为灰度，再以大于零作为前景，不能额外使用常规 DB 的 0.3 阈值收缩范围。真实安装依赖的纯后处理检查覆盖 Float32 量化边界及低概率合法检测；平面一致不代表语义分割正确。模型输入输出与锁定 SDK 的实际尺寸配置须符合原比例加 32 倍数填充；放大、旋转及未证明映射均无旁证。每页最多 128 个捕获尝试、4,194,304 个概率检查和 512 KiB 位图，坏概率与失败也占预算。消费者把校验后的自有字节绑定到实际结果数组、原图和尺寸，分组或克隆不能冒领；必须有单个真实帧覆盖完整观察域及两像素查询余量，不能跨瓦片拼接半份证据。原图已有透明度扫描确认不透明时，不捕获或复制侧车。检测位图仍是模型观测，不能称为语义真值，也不会放进阅读或缓存结果。

`imageDetectionSnapshot` 对补充修补路径检查已解码数据的单帧资格：相符签名的 JPEG/BMP，或完整 PNG 块中没有动画控制。动画、SVG、未知格式或无完整单帧证明时沿用原图回退，避免同一 URI 换帧后使用旧检测。此检查不替代图片解码或 CRC 校验，也不改变既有成功绘制路径。

这一补充路径要求整页所有物理源框、原文与数字保护、跨区域图案冲突及完整译文字形都通过后才写入，不发布截断句子。清字仅将确认的墨迹恢复为同次观测底色，避免把透明或不透明边框当成扩散种子。上传按精确墨迹行段纵向合并的脏矩形进行，不能使用文字支持包络扩大写入，也不能把整页 alpha 套回去裁掉新字。普通不透明成功路径仍沿用原有读写和测量。

局部观察最多外扩八像素、每处 65,536 像素，整页最多 128 次物理框证明；局部观察面积与绘字扫描面积共同预扣 1,048,576 像素。每个观察区域仍可有最多八种背景候选的有界多遍证明，因此该面积额度不是全部实际像素访问次数。比较和保护行段另有共享上限，上传矩形与图案保护矩形各最多 4,096 个，全文度量也有整页额度，度量及拆分累计 UTF-16 工作也预付额度，超额整页回退。脏矩形不等于浏览器保证只复制其面积；真实上传调用数、时延和内存须由原生运行另行验证。模型、几何和颜色证据仍不能把同色相连装饰与文字作普遍语义区分，受控像素回归不替代原生字体、真实 OCR 和供应商验收。

回退使用固定 Unicode 17.0.0 的 Extend／SpacingMark／ZWJ／Prepend 区间，测试读取仓库内的官方原始属性文件独立核对，不在 CI 访问网络。运行 `node scripts/generate-image-grapheme-space-data.mjs --check` 校验离线生成与输入 SHA-256；来源、版本和许可见 `public/third-party-notices/image-grapheme-space-NOTICE.md`。该表只支持 ASCII 空格的局部边界判断，不是完整 UAX #29 分割器，也不声称恢复模型漏识别的文字。

### 漫画质量场景与模型复用

自然图片排版复核可追加 `--translation-map <JSON文件>`，按精确识别段落提供固定译文。未命中的段落使流程失败，报告记录映射文件摘要；这用于检查真实 OCR 后的整段排版，不能代表在线翻译质量。诊断时可追加 `--trace-ocr`，记录有界的原始行框、置信度和段落证据，不复制模型张量或图片像素。

普通图片质量样本进行在线验收时，组合 `--live-translation --live-text-allowlist <字符串数组JSON>`，仅发送显式允许的测试文本；只忽略空格差异，未命中时整批拒绝联网。可通过 `--runtime-diagnostics-helper <runtime-diagnostics.cjs路径>` 在导航前采集内容脚本、扩展页面和后台诊断，错误与告警阻止通过；采集缺口保留在报告中。

`image-translation/paragraph-gaps` 的两处原图像素裁片复现白底与深蓝气泡的小字断段，校验源 PNG 和 RGBA 摘要。OCR 坐标来自生产模型记录，测试置信度为受控高值；原生模型验收仍通过自然图片专项执行。竖排列框回映、两视图对象隔离、变音符号墨迹边界和渐变修补另有定向回归。

漫画专项和图片专项的 `--x-lightbox` 模式默认复用主仓库旁 `workspace-data/model-cache/` 中的公开 PaddleOCR／LaMa 文件。可用 `--model-cache-dir <目录>` 或 `FLUENTREAD_TEST_MODEL_CACHE_DIR` 指定位置。每次使用都按生产清单检查长度与 SHA-256，缺失或损坏才下载；并发测试共享逐文件锁。文件通过原有导入入口放入全新的临时浏览器，不复用日常 profile。报告记录每个文件的命中来源、下载数及导入状态。普通图片只准备 OCR，漫画按需包含修补模型；模型下载、来源故障和离线导入专项保留各自原有路径，不用缓存掩盖这些行为。Tesseract 语言包不在这份共享权重缓存内。

固定 PP-OCRv6 识别模型在全部原文件 SHA-256 校验及原始缓存写入完成后，仅为会话生成形状计算简化的内存副本：保留特征权重和原 Reshape，只用两个 INT64 常量替换十三个形状节点及十一项无消费者常量。缓存版本、原文件 SHA、离线导入、下载回退和像素预处理保持原契约，不为该副本重下模型。该等价关系仅覆盖私有识别入口的 `float32 x[N,3,48,W]`，`N` 为正整数，`W` 为至少 8 的整数；入口明确固定高度 48，每次原生识别调用前检查输入域，CPU 回退复用同一资源路径和原 feeds。固定来源的容量或配方漂移明确失败，不能误删有效缓存后重新下载。纯 wire / 配方 / 输入域、资源生命周期及 GPU→CPU 端口回归分别验证这些边界；它们不证明 OCR 空格、段落或漫画绘制质量已经改善，也不代表跨设备或竞品的性能结论。

默认目录从测试 helper 所属仓库的 `git common-dir` 定位，因此从其他工作目录启动也复用同一缓存；源码快照无法定位 Git 时才回退到调用目录的 `.cache/image-translation-models/`。环境变量指定的相对路径以调用目录为准。

颜色适配只处理 SDK 原识别缩放副本的一次既有四参数整幅读回，先恢复上下文方法再读取原生 ImageData，保留原生异常及其他参数语义。完整不透明边缘的 R 必须共享 0 或 255 端点，完整 alpha 校验后才增强副本对比；灰阶保持原值，不修改原画布或 RGB 检测输入。每裁图最多 262144 像素、每原页最多 2000000 处理像素，整页切片、气泡和复识别共享此颜色预算，另有的斜行/反向预算与四次重试不变。没有额外像素读写、归一化像素数组或画布，但仍有颜色扫描及待消费裁图的恢复闭包；不能宣称零 CPU 或零总分配成本。单次读回前恢复方法并立即移除已消费闭包，避免适配层跨推理继续持有裁图上下文；未读的 hook 在原 run 实际收尾后恢复。取消、fetch/decode/画布失败与原页 finally 分别验证预算、信号和 bitmap 所有权。

`tests/fixtures/manga-structures/manifest.json` 再提供单独运行的五景，结构分别为大型气泡中的窄白卡、跨越气泡中段的上下独立卡片、装订跨页与书脊文字、多字号注音与图解引线、带阴影和透视的拍摄纸页及便笺。包含 29 条完整原文锚点、23 个段落组和 8 个无字区域；不修改已有 38 景，不扩大单次 32 景上限。设计、字体、图片及真值在首次 OCR 前固定；`python3 scripts/testing/generate-manga-structure-fixtures.py --out-dir <新目录>` 仅写入新目录，`node scripts/testing/check-manga-structure-fixtures.cjs` 无需模型检查冻结内容与反例。首轮真实浏览器结果保存在同目录 baseline：窄白卡、跨中段卡片和多字号注音三景通过，跨页和透视场景仍有漏字或分段失败，不把 26/29 锚点命中写成全部通过。

新场景的 `paragraphGroups` 引用真实源文字区域，允许单行卡片和横排标签。每区锚点必须等于该区完整规范化原文，并同时属于 `expectedSource` 与 `expectedAnchors`；每组按源顺序完整匹配一个实际 OCR 段落，各组须占不同段落。独立卡片混入正文、主列被拆散、顺序颠倒或借用别段子串，即使总锚点与字符库存齐全也失败。原 `readingOrder`／`readingOrderGroups` 的竖排契约保持；三种声明互斥，不能用新格式放宽旧夹具。

彩色八景另有显式角色补充 `tests/fixtures/manga-color-quality-roles.json`，通过 `--quality-roles` 传给真实驱动。它绑定完整原 manifest 的 SHA-256，不修改原图、原文、出现次数或历史分数。实际 `ruby` 元数据也参与全部 34 个锚点和字符库存，且须匹配原注音位置、父正文及唯一物理框；独立翻译读音、重复、漏读、错归属或凭期望补字都失败。视觉组只能按顺序拆分原语义组，不能合并独立内容，并须完整文字与源坐标同时匹配不同实际区域；原语义组的视觉部分仍须连续、按源顺序出现。旧评分保存在每景 `legacyQuality` 和汇总 `legacyFailures`，默认不带角色参数时原评分行为不变。已有真实记录 `manga-role-recording.json` 仍会因漫画标题误合并而失败，补充规则不能把它改判通过；静态回放不代替当前浏览器、空格/CER 或真实翻译语义验收。

逐列渐变的额外续行不只看背景：两行墨迹高度差超过 20% 时，在原 RGBA 上最多额外预付 262,144 像素观察面积并复用同页色值。两个可确认源色之间的局部对比达到 3 时撤回这条额外合段关系，保留大小、颜色不同的独立标题；未知颜色沿用原规则。该额外额度与原走廊预算分开记录，不新增画布读回、模型推理、文字或擦除权限。

完整确认均匀背景的漫画页可复用本次 Offscreen 请求独占的 ImageData，避免整页临时数组与同数组拷回；修补 API 默认仍返回独立副本，复杂页保留输入与输出分离。`scripts/testing/benchmark-manga-owned-pixels.cjs` 用真实专项报告的源 PNG、识别框和背景分类，对比指定 Git 基线与当前工厂及实际拷回语句，核验受控原生输入张量、蒙版和最终 RGBA 一致。报告中的字节数是累计分配和拷贝量；局部返回与拷回计时不包括 OCR、模型、Canvas 和 PNG 编码，不能当作整页提速或进程峰值内存。取消、删除模型准入、FIFO 和引用所有权由修补与 Offscreen 专项分别验证。

为下面的漫画浏览器专项传入 `--quality-manifest <证据目录>/corpus/manifest.json`，逐图运行真实 OCR，以明确的原文锚点及出现次数核验识别，检查实际物理行是否进入无字区域、原文字符是否超出真值库存、保护像素、恢复原图和缓存重显；无字页须保持零识别文字、零文字翻译请求且不遮盖原图。每张图片的原语言来自 manifest。锚点、阅读顺序和误报失败保留到逐景报告，全部场景完成后统一失败；像素和缓存等结构错误立即失败。字符库存只检测多余字符，不能替代缺字、顺序及位置检查。翻译 transport 受控，因此这些结果不代表在线翻译模型的语言质量。原有 `--pipeline-inputs <图片列表> --pipeline-rounds 2` 仍用于区分冷启动与热运行，不把首次下载耗时混成推理性能。

同一脚本加 `--quality-profile image` 可单独验证普通图片模式：关闭漫画连续翻译，以实际悬停按钮完成翻译、恢复和缓存重显，保留全部锚点、库存、阅读顺序、保护像素及请求次数检查。按钮必须位于视口内且能命中，不能用脚本触发替代可信点击。此模式接受受控的 en/ja/auto 质量 manifest，包括明确标记 `expectedNoText` 的无字负控；无字页的零文字传输、无译图和可见原图分别参与失败判据。透明图可仅声明合法 `protectedAlphaProbes` 而令 `protectedProbes` 为空，不能同时缺少保护点；逐点比较同次原生采样的原图与输出完整 RGBA，不用作者 RGB 替代 Canvas 量化值，允许翻译的源字形不属于保护点。不与其他阅读专项、预取或旧模型来源诊断参数混用，通过 `--model-cache-dir` 只准备三个 OCR 模型文件，不导入 LaMa；与漫画模式分开报告，同一图片的两个模式不能算两张独立场景。双语菜单、透明通知、小字车站截图、多栏报纸和聊天截图可作为普通图片回归输入，真值应在首次 OCR 前固定。

普通图片仅在 OCR 真正返回空数组时使用既有的轻量原图保留协议，显示“未检测到文字，已保留原图”，不请求翻译或创建译图；恢复后按相同来源和配置复用结果，来源或配置改变后重新识别。非空结果因数字保护或置信过滤而不可读时仍报错，不能把不确定识别当成成功空页。漫画的空页协议保持。

漫画文字面板使用隔离根内自带默认值的语义配色和紧凑控件，分别检查明暗主题、按钮悬停与焦点、窄窗口和完整内容滚动。组件交互测试验证选择、复制、取消和焦点归还；真实 Shadow 样式验证须另存截图和 computed style，不能把自定义 renderer 或入口资源说明面板当作阅读面板的原生验证。

质量矩阵根据真实 Offscreen 完成响应检查返显。漫画未识别到文字，或只识别到无需改写的时间数字而保留原图时，仍记录全部缺失锚点和段落失败并继续后续场景；不能因没有译图而一直等待，也不能用预期无字标记代替实际返回值。实际 layout 记录保留 `renderSkipped` 和 `numericUncertain`，用于区分已识别但为保护画面而未绘制的文字；缺少这些标志不能作为没有跳过绘制的证据。识别质量与背景清理效果分别检查，锚点通过并不证明原字已完全擦除。

Paddle 后处理保留置信度至少 0.9 的连续多位数字、有效时间日期及带货币符号金额；判定时规范化全角字形，输出仍保留识别原文和物理框，孤立数字、空格数字碎片与低置信绘画噪声继续过滤。检测裁框按原始字行短边计算留白，避免长竖列把邻列或注音夹入识别输入；检测平面短边不足 12 像素时保留 SDK 原高度留白及识别路径，这是有界的裁切输入策略，不删除细小文字或调整识别门槛。通过 SDK 公开处理器复用原检测会话，保留检测平面的裁边、舍入与缩放。水平原始框的语义保持，不能只按最终框宽高比推断原始方向。留白也会改变原尺寸筛选后的框数和按宽度补齐的识别批次，因此须核验整页原文、误报及实际推理次数。

低置信竖列复识别与倾斜水平行校正共享每页最多四框。仅对模型当前已读到拉丁字母且不含 CJK 的低置信高窄框，在原重试配额内尝试相反方向；其他文字继续原批次复识别，返回框不移动，仍须比原置信度提高至少 0.05。方向裁图和水平校正共享每页两百万预处理像素，超出方向预算时走原重试路径。水平校正只处理近白底、清晰墨迹及 3–15° 倾斜，源框与旋转结果读取面积共同计入预算，旋转画布另有硬上限；不得用期望文字选角。水平校正结果须至少 0.99 且比原置信度提高 0.01 才替换文字。这些门槛不能代替实际质量回归或保证所有字体准确。

同一次扫描把局部识别候选和段落归属分开：原有最多二十四处、面积至多全页 15% 的裁图预算不变。15–40% 的大型浅底连通组件仅在密度、上下曲边与行包络实心度均满足保守边界时提供中段内接矩形，避免将椭圆包围框的角落当作气泡内部。候选还须由已有原像素确认物理框边缘十二点至少九点为浅底，成员索引绑定未重排的原 OCR 结果。同次扫描记录其原组件外接框内后续发现的独立白色岛；物理文字框完整落在岛内时保持独立，避免窄白卡并入正文，字形孔洞仅覆盖部分文字框不会剥离整行。每个大型候选最多保留 128 个岛，超限撤回该新增归属，沿用原分组，不删除原文。岛列表不传到主线程。这不会增加 OCR、像素回读或第二次组件扫描；最紧气泡优先。只有同一气泡内的同字号、纵向重叠竖列可使用较宽的有界列距；页面、横排和普通图片维持各自原有合段策略。矩形、多洞面板、曲边角落、内部黑底及窄白底卡片、跨内接框的白卡、相邻独立气泡均有反例回归；形状、发现顺序与少量底色采样仍是启发式，不能保证辨别所有画风或与气泡连通的白底标签。

漫画译文以实际 Canvas 字形上下界、描边及像素余量适配原识别框，缺失或非法指标退回完整行框；不通过扩大擦除范围提升字号。度量、补绘预检和最终绘字统一采用整段译文首个强方向字符的方向，数字与标点行仍沿用所属段落；结束后恢复调用方 Canvas 状态。单次绘制的字体族固定，度量缓存用方向、字重、字号与全文短键，连续字号复用前缀；准入按完整字体键加方向计费，保持 8192 条、131072 个逻辑 key 字符预算。字形回调先全部完成再读取指标，兼容回调复用或修改同一对象。字形适配可能增加局部排版计算，需要分别报告可读性、度量调用量与耗时。Node Canvas 的字体回退指标可能与真实浏览器不同，离线像素检查不能替代浏览器实际渲染与禁裁剪越界检查。受控原生回归可用 `--target-language ar` 或 `he` 配合 `--translation-map`，记录实际 Canvas direction；这不测量在线翻译质量，绕孔拆片仍拒绝不支持的双向文本，转为完整连续矩形排版。
